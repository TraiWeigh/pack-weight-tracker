ROOT CAUSE DIAGNOSIS
─────────────────────
Two separate issues caused the camera/photo box to be unresponsive on iPhone:

Issue 1 — PHOTO ROW OUTER DIV HAD NO ONCLICK
  The expanded item detail panel's Photo row (Camera icon + "Photo" label +
  small "Add Photo" button) is 44 px tall and looks like a tappable iOS row.
  However, only the small right-side "Add Photo" button (~36 px, right-aligned)
  had an onClick handler. Tapping the Camera icon or the "Photo" label text
  (the left 2/3 of the row) did nothing — no handler, no visual feedback.

  On iPhone, users naturally tap the camera icon or the row label, not the
  small text-button at the far right edge.

Issue 2 — PHOTO-MODE IMAGE WAS A BARE <img> WITH NO STOPPROPAGATION
  The photo card in Photo filter mode rendered the photo as an <img> element
  with an onClick callback but no stopPropagation() and no native button
  semantics. iOS Safari can silently drop click events on non-button elements
  (div, img) when there is no cursor:pointer or role="button" established at
  the element level. The fix wraps the image in a proper <button> element.

IMPLEMENTATION — MINIMAL FIXES
────────────────────────────────

Fix 1: Make the entire Photo row tappable when no photo exists.
  Changed the outer container div of the Photo row in the expanded item detail
  panel to have onClick + cursor:pointer + data-testid="item-photo-row" when
  item.photoDataUrl is falsy. The inner "Add Photo" button (item-photo-add-btn)
  retains its own onClick with stopPropagation, so clicking it directly does
  not double-fire the outer div handler (stopPropagation prevents bubbling).
  When a photo already exists, the outer div has no onClick (cursor:default,
  no testid) — the View Photo / Edit Photo buttons handle interaction.

  data-testid="item-photo-row" — present only when no photo; used in tests
  to click specific subregions (camera-icon area, label area).

Fix 2: Wrap the photo-mode card image in a <button>.
  The bare <img> is now:
    <button type="button" data-testid="photo-mode-img-btn" onClick={e => {
      e.stopPropagation(); setPhotoEditFor({cat, id});
    }} aria-label="Edit photo of …" style={{display:'block', …}}>
      <img data-testid="photo-mode-img" src={…} alt={…} style={{…}} />
    </button>
  stopPropagation added. data-testid="photo-mode-img-btn" on button,
  data-testid="photo-mode-img" on img (for the R0103 img[data-testid] selector).

THREE STANDING REPLIT QUESTIONS
─────────────────────────────────
1. What did you learn that improves future prompts?
   "The camera box is not responding" means the outer container div of a
   detail-panel row lacks an onClick — only the right-edge button responds.
   On mobile, users expect the full row to be tappable. Any detail-panel row
   that looks interactive must have onClick on its outer container, not just
   on a small inner element.

2. What was unclear, unnecessary, risky, or better expressed?
   "camera/photo box" most precisely means: the 44 px detail-panel row that
   renders a Camera icon, a "Photo" label, and a small Add Photo button.
   Calling it "the row" or "the Photo row" would be clearer in future prompts.

3. What Replit/project guidance helps next time?
   iOS Safari can drop click events on bare <img> and <div> elements even
   with cursor:pointer set. Always wrap tappable non-text content in a
   <button> element when targeting Safari. The stopPropagation pattern
   (inner button stops, outer container still fires when not overlapping)
   avoids double-calls while making the full row tappable.
