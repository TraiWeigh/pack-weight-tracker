IMPLEMENTATION SUMMARY
──────────────────────
Three behavioural changes shipped together as a single GS:

1. NAME FIELD IN ITEM ACCORDION (expanded item detail panel)
   A directly editable text input is now the first row in every expanded item
   detail panel, sitting above Weight. It shows the item's current name and lets
   the user edit it in place — no swipe-Edit, no separate rename dialog required.

   Edit commit rules:
     Enter key  → blur() → onBlur calls updateItem(cat, id, { desc: v }, { edit: true })
     Blur       → same commit path
     Escape     → DOM value reset to committed name before blur so onBlur sees no
                  change and updateItem is NOT called (revert, no save)

   Local edit state uses the same Record<string, string> pattern as weightInputs
   so intermediate keystrokes don't snap back while the user is typing.

2. ACCORDION NAME → CREATE + EXPAND + FOCUS
   Tapping the "Name" row in the R0102 creation accordion now:
     a. Pre-generates a UUID (same as R0102 Photo method)
     b. Calls addItem(catName, { id: newId }) — one item created
     c. Sets expandedItem({ cat: catName, id: newId }) — opens that item's panel
     d. Sets focusItemNameId(newId) — schedules auto-focus after paint
     e. Closes the creation accordion

   A useEffect([focusItemNameId]) fires after the DOM is ready, queries
   [data-item-name-id="{id}"] and calls .focus(), then clears focusItemNameId.

3. SWIPE EDIT REMOVED FROM ITEM ROWS
   The secondaryAction prop is removed from SwipeDeleteRow on item rows.
   Swipe-left still reveals only the Delete action.
   Category rows and master-list rows retain their Edit actions unchanged.

4. PHOTO-MODE <img> IS NOW TAPPABLE
   The large photo <img> in photo-mode item cards now has:
     onClick={() => setPhotoEditFor({ cat: catName, id: item.id })}
     cursor: 'pointer'
   Opens the identical photo-edit sheet that the "Edit" button below it calls.

IMPLEMENTATION NOTES — ESCAPE BUG FIX
──────────────────────────────────────
Original Escape handler called .blur() after clearing nameInputs. The blur
handler reads e.target.value (still the dirty DOM value) and would call
updateItem with the temp text. Fix: set e.target.value = originalValue BEFORE
clearing nameInputs and calling .blur(), so onBlur sees no change.
