IMPLEMENTATION SUMMARY
──────────────────────
Tapping Add Item on /mobile-functional-v3 no longer immediately creates a blank
item row. Instead it toggles a 3-row creation-method accordion that sits directly
above the locked Add Item bar. The accordion reuses all existing flows.

Creation methods
  Name        → addItem(catName) — blank row, user types inline (existing flow)
  Photo       → pre-generates UUID, calls addItem(catName, { id }), then
                setPhotoEditFor({ cat, id }) — existing camera/upload sheet opens
  Master List → pushScreen({ screen: 'master-list' }) — existing MasterListScreen
                overlay. Limitation: MasterListScreen has no onAddToCategory
                callback; browsing only. Adding from it to the active category
                is a future enhancement (documented, not invented).

Accordion rules
  • Opening/closing alone never changes item count.
  • Auto-closes when the category closes or a different one opens (useEffect on
    openCatName).
  • In allExpanded mode the button retains direct-create behaviour (unchanged).
  • aria-expanded on cat-add-item-btn reflects accordion state.
  • Icon changes from Plus → ChevronDown when accordion is open.

Geometry (R0101 preservation)
  • ADD_ITEM_ACCORDION_H = 3 × 44 = 132 px constant.
  • remeasureLongMode subtracts accordionH from rawAvailH so availItemH
    shrinks by 132 when accordion is open for the bounded category.
  • A second useEffect fires remeasureLongMode() whenever addItemAccordionCat
    changes, keeping isCatLong and availItemH immediately correct.
  • Filter, AppBar, List Summary, active category header remain locked.
  • Add Item bar remains locked directly above Bottom Box Groups.
  • R0101 scroll restore unchanged (openCategoryScrollRef path untouched).
