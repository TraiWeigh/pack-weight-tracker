Every category auto-locks beneath the visible Filter bar when opened, scrolling
its header to sit flush against Filter's bottom edge. Pre-open list position
is saved and restored when the category is closed. Short lists and last
categories can reach the lock position via main-scroll's natural scroll range.
The Filter bar remains visible throughout (superseding R0096's old behaviour
that hid Filter when a bounded category was active).

R0100 wedge shadows, R0099 Bottom Box Group looping, R0098 1 px wedge gap, and
R0097 locked mobile shell are fully preserved.

2a. showFilterSlot hardwired to true (line ~2752)
    Previously toggled off for long categories. Now permanently true — the
    Filter slot is always rendered.

2b. openCategoryScrollRef
    New ref { catName, scrollTop } captures main-scroll position immediately
    before opening a category. Set in handleCatToggle.

2c. R0101 main open/close effect
    Replaces the old shared-slot scroll logic.
    On OPEN (openCatName set):
      RAF1: reads filterEl.getBoundingClientRect().bottom, scrolls
            main-scroll.scrollTop so the category header aligns with filterBtm.
      RAF2: applies sub-pixel residual correction, then calls
            remeasureLongMode() to establish bounded-mode if item count warrants.
    On CLOSE (openCatName cleared):
      Two-RAF restore: assigns saved scrollTop twice (second frame catches
      Safari's layout flush after the collapsed DOM settles).
    Deps: [openCatName, isCatLong, allExpanded, summaryH, navHeight, showFilterSlot]

2d. remeasureLongMode — sticky-header fix
    Root cause: when the Add Item button scrolls below the viewport as items
    grow and the auto-scroll (Playwright or real-touch) moves main-scroll down,
    itemsEl.getBoundingClientRect().top goes negative. This made rawAvailH
    artificially large, so isCatLong never became true.

    Fix: climb the DOM from itemsEl to the [data-cat] row, find the
    [data-testid^="cat-header-"] element, and read its
    getBoundingClientRect().bottom (the sticky header is always pinned at
    filterBtm regardless of main-scroll position). rawAvailH is then:
      navTop - catHeaderBottom - addItemBarH(44)
    useCallback deps updated: [navHeight, summaryH]

2e. data-long-mode attribute on open-cat-items
    data-long-mode="true" set when isCatLong is active. Provides an explicit
    DOM observable for automated tests; no user-facing effect.

2f. Overflow exception for active category row
    The [data-cat] row of the currently anchored category uses overflow:visible
    so its position:sticky header is contained by main-scroll rather than by
    the row itself. All closed rows remain overflow:hidden.

2g. R0096 test update (r0096-locked-controls.spec.ts)
    makeBackpackLong() updated to:
    - Not assert Filter hidden (R0101 supersedes that behaviour).
    - Wait for data-long-mode="true" as the explicit long-mode DOM signal.
    - Geometry assertions: filter visible, filter.bottom ~ active.top (stacked).
