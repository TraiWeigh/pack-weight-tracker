### Implementation notes (Part 8)

Two non-obvious fixes were required for true finger-follow:

- **Window-level drag listeners.** The live reorder preview moves the dragged card's DOM node, and the browser fires `lostpointercapture` on the grip the moment that happens — element-level capture cannot survive a row crossing. pointermove/up/cancel are now tracked on `window` for the duration of the drag (cleaned up on release, cancel, and unmount). Any `pointercancel` still aborts without committing.
- **Lifecycle hardening (post-review).** An independent review round flagged three races in the window-listener rewrite; all fixed and test-covered:
  - `pointercancel` is now filtered per pointer — an unrelated second pointer's cancellation no longer aborts the active drag (cancellations dispatched at the category list itself still count, covering gesture-takeover).
  - A replacement pointerdown fully cancels the previous drag, and the dragged category is resolved by NAME against the saved order — never by rendered slot index, which diverges from the data order while a live preview is showing.
  - `window` blur / document hidden cancels the drag without committing, so a tab/app switch can't leave a stuck floating card.
- **Untransformed slot geometry.** The floating card's own large translateY otherwise pollutes both the destination-slot scan and the lift math; the rendered transform (read from the computed matrix) is subtracted so slot detection and lift are computed against the card's real slot.
