## What was built

The existing `handedness` state (persisted to `localStorage` key `tw-handedness`, introduced in R0082) now controls the position of two interactive controls on every category row and every item row:

| Control | Left-handed (default `'left'`) | Right-handed (`'right'`) |
|---|---|---|
| Category wedge / accordion trigger | **Far left** of the category header | **Far right** of the category header |
| Item packed/checked checkbox | **Far left** of the item row | **Far right** of the item row |

Everything else — category names, item names, weight values, quantity values, selected counts, expanded detail panels, reading order — stays in its normal left-to-right position regardless of handedness.

Switching handedness via the R0082 drawer toggle repositions both controls **immediately** without a page reload, and is fully reversible.

## Implementation — four targeted edits, one file

All changes are in `artifacts/pack-checklist/src/pages/MobileFunctionalV3.tsx`. No new files, no new props, no new components. `handedness` was already in scope as a `useState` variable in the same component body that renders category headers and item rows inline.

### Technique: CSS `order` on individual flex children

Rather than `flex-direction: row-reverse` (which would flip reading order across the entire row), the `order` CSS property is set on only the two interactive controls:

```
order: handedness === 'right' ? 2 : 0   ← wedge button
order: 1                                 ← content grid (pinned in the middle)
order: handedness === 'right' ? 2 : 0   ← checkbox button
```

This moves the wedge or checkbox to the last flex position (far right) when `handedness === 'right'`, while leaving all text and weight columns in their natural left-to-right order.

### Edit 1 — Wedge button (category header)

- `order: handedness === 'right' ? 2 : 0` — moves wedge to far right in right-handed mode
- `clipPath` — flips the arrow direction: right-handed uses `polygon(${WEDGE_POINT}px 0, 100% 0, 100% 100%, ${WEDGE_POINT}px 100%, 0 50%)` (◀) so the point still faces inward toward content
- `paddingRight` / `paddingLeft` — swap so the icon remains visually centred within the wedge shape

### Edit 2 — Content grid (category header)

- `order: 1` — explicit pin keeps the name/weight grid between the two edges regardless of wedge position

### Edit 3 — Checkbox button (item row)

- `order: handedness === 'right' ? 2 : 0` — moves checkbox to far right in right-handed mode

### Edit 4 — Expand area (item row)

- `paddingRight` / `paddingLeft` swap — breathing-room padding follows the open edge (opposite the checkbox side)

## Design decisions

- **CSS `order` not `flex-direction: row-reverse`** — the latter flips the entire row including text; `order` on individual elements is surgical and leaves reading order intact.
- **Wedge clip-path mirrored** — the arrow shape (◀/▶) always points toward the category content, not toward the screen edge. In right-handed mode the wedge is a left-pointing shape on the right side; in left-handed mode it is a right-pointing shape on the left side.
- **Padding swap on both controls** — the "breathing room" padding follows the open edge (the side with no control), keeping visual balance consistent.
- **Swipe-delete deliberately unchanged** — the user's instruction was explicit: only the wedge and checkbox move. Swipe-delete is a separate gesture from a separate edge; mixing handedness into it is a future decision.
- **Content grid `order: 1`** — without an explicit order pin the browser could re-sort it relative to the wedge; the pin makes the intended middle-slot position unambiguous.
