# R0079 — Locker Delete + Save / Save As + Reset Checked State

**Route:** `/mobile-functional-v3`  
**Date:** 2026-08-17  
**Status:** ✅ COMPLETE — 19/19 tests pass, 74/74 regression tests pass

---

## A. Overview

Surgical mobile list-workflow repair covering three independent features on the `/mobile-functional-v3` route:

1. **Locker Delete** — per-entry Delete button inside expanded Locker cards, with a confirmation bottom-sheet before removal.
2. **Save / Save As** — Save NavBox now opens a chooser (Save / Save As / Cancel) instead of immediately duplicating the list; Save updates the active entry, Save As always creates a new independent copy.
3. **Reset** — Reset now clears only checked/packed marks (not restores original seed data), with a confirmation bottom-sheet.

No app-scope changes: no auth, no schema, no deployment, no Preview/Print, no photos/locations, no looping nav.

## C. Implementation

### New localStorage helpers (module-level in MobileFunctionalV3.tsx)
```
writeLockerEntries(entries)       — replaces full locker array
updateLockerEntry(id, patch)      — updates one entry in-place
removeLockerEntry(id)             — removes one entry by id
```

### New state
```
activeLockerEntryId: string | null   — tracks which entry is currently loaded
lockerDeleteTarget: LockerEntry | null — pending delete dialog target
showSaveChooser: boolean             — controls Save chooser bottom-sheet
showSaveAsDialog: boolean            — controls Save As name dialog
saveAsName: string                   — controlled input for Save As name
showResetConfirm: boolean            — controls Reset confirmation bottom-sheet
```

### handleSave → branched
- If `activeLockerEntryId` is set → `updateLockerEntry` (in-place update, no duplicate)
- If no active entry → `appendLockerEntry` (first save, creates new entry)
- Active entry id is set on first Save and on Load

### handleSaveAs
- Always creates a new `LockerEntry` with a fresh `crypto.randomUUID()`
- Sets `activeLockerEntryId` to the new entry's id

### handleReset → checks-only clear
```typescript
setCategories(prev => prev.map(cat => ({
  ...cat,
  items: cat.items.map(item => ({ ...item, checked: false })),
})));
```
Items and categories are never removed; only `checked` flags are cleared.

### Locker Delete flow
- Delete button in expanded card: `setLockerDeleteTarget(entry)`
- Confirm: `removeLockerEntry(id)`, refresh `lockerEntries`, detach `activeLockerEntryId` if it matches
- Edge case: deleting the active entry detaches identity (`setActiveLockerEntryId(null)`) but keeps working list in memory; next Save creates a new entry

### Four new confirmation dialogs (all follow existing R0077 pattern)
| Dialog | aria-label | Initial focus | Escape |
|--------|------------|---------------|--------|
| Save chooser | `Save options` | Cancel | closes |
| Save As | `Save As new copy` | name input | closes |
| Reset confirmation | `Reset Checklist confirmation` | Cancel | closes |
| Locker delete | `Delete Saved List confirmation` | Cancel | closes |

Reset confirmation uses amber (`#b45309`) — not destructive red — since no data is deleted.

## G. Key Technical Decisions

- **DeckCardItem uses pointer events** (onPointerDown/Up), not onClick. Tests must use Playwright's `.click()` (fires pointer events) rather than `.evaluate(el.click())` for deck card activation.
- **Save chooser always shows**: even for an unsaved list, the chooser appears; "Save" creates the first entry and sets `activeLockerEntryId`. This is correct — users should always be aware of the Save vs Save As distinction.
- **Reset is checks-only**: `DEMO_SEED` is no longer restorable via Reset. This is intentional — Reset should be a trail-side action to uncheck everything, not a way to lose edits.
- **Active-entry detach on delete**: rather than clearing the working list (which would destroy unsaved changes), deleting the active entry merely detaches the identity. The working list remains editable; the next Save creates a fresh entry.
