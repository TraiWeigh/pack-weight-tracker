## What changed

### 1 — Category swipe secondary action: Open/Close → Rename

**File:** `artifacts/pack-checklist/src/pages/MobileFunctionalV3.tsx`

The `secondaryAction` on category `SwipeDeleteRow` (previously `Open/Close` with `ChevronUp/Down` icon) was changed to `Rename` with `Pencil` icon. Tapping it sets the three existing category-rename state atoms (`setCatOptionsFor`, `setCatRenaming`, `setCatRenameValue`) in a single handler, opening the Category Options Sheet directly in the rename sub-view — bypassing the main options list. No new code was written for the sheet or its sub-views; they were already complete.

```tsx
secondaryAction={{
  label: `Rename ${catName} category`,
  icon: <Pencil size={15} strokeWidth={1.9} aria-hidden="true"/>,
  onAction: () => {
    setCatOptionsFor(catName);
    setCatRenaming(true);
    setCatRenameValue(catName);
  },
}}
```

**Tap-anywhere category toggle** (R0083P2) is completely preserved. The `onClick` on `cat-header-<name>` div still calls `handleCatToggle(catName)`. The swipe gesture and the tap path are independent; the disambiguation slop (`SWIPE_SLOP_PX = 8`) ensures a horizontal swipe never fires as a tap.

### 2 — Item swipe: add Rename secondary action

**File:** `artifacts/pack-checklist/src/pages/MobileFunctionalV3.tsx`

Item `SwipeDeleteRow` previously had no `secondaryAction`. Added:

```tsx
secondaryAction={{
  label: `Rename ${displayName}`,
  icon: <Pencil size={15} strokeWidth={1.9} aria-hidden="true"/>,
  onAction: () => {
    setItemRenameFor({ cat: catName, id: item.id, currentDesc: displayName });
    setItemRenameValue(displayName);
  },
}}
```

`totalRevealW` inside `SwipeDeleteRow` automatically doubles to 176 px when `secondaryAction` is present. All gesture math (clamp, half-way commit, resting position) is derived from `totalRevealW` — no manual arithmetic change needed.

### 3 — New item rename state (2 atoms)

```tsx
const [itemRenameFor, setItemRenameFor] =
  useState<{ cat: string; id: string; currentDesc: string } | null>(null);
const [itemRenameValue, setItemRenameValue] = useState('');
```

Mirrors the shape of the existing `deleteItemConfirm` state. No new hooks or helper functions.

### 4 — New item rename bottom panel

A fixed-position overlay (`zIndex: 200`) with a bottom-anchored sheet — identical visual language to the existing item delete confirmation modal:

- **Title:** "Rename Item"
- **Subtitle:** `New name for "${currentDesc}":`
- **`autoFocus` text input** (`data-testid="item-rename-input"`, `aria-label="New item name"`)  
  Pre-filled with `displayName`. `Enter` key commits if value is valid.
- **Cancel button** (`data-testid="item-rename-cancel"`, `minHeight: 44`) — dismisses, no mutation.
- **Rename button** (`data-testid="item-rename-confirm"`, `minHeight: 44`) — disabled when input is empty or unchanged; calls `updateItem(cat, id, { desc: newName })` and `showToast(...)` on confirm.
- **Escape key** dismisses without mutation.
- **Backdrop tap** dismisses without mutation.

**Master Library semantics:** This rename updates only the local list copy (`desc` field on the sandbox item). No Master Library mutation occurs. The comment in code documents this explicitly: "List-only rename: updates desc on this list's copy only. Master Library linking is a future feature; no fake mutation here."

## Touch target compliance

All revealed action buttons use `position: absolute; top: 0; bottom: 0; width: 88px` — height inherits from the row. Category rows are `minHeight: CARD_H (68 px)`; item rows are `minHeight: 44 px`. Both exceed the 44 pt / 48 dp threshold.

Tests R84-T320 through R84-T430 assert `height ≥ 44` on both category and item Rename buttons at 320, 375, 390, and 430 px viewports. All 8 assertions pass.

---

## Horizontal overflow

`SwipeDeleteRow` wraps content in `overflow: hidden`. The 176 px total reveal is clipped, never widening the document. At 320 px (narrowest tested width): visible content = 320 − 176 = 144 px, with item content (`whiteSpace: nowrap; textOverflow: ellipsis`) not overflowing. `document.documentElement.scrollWidth > clientWidth` returns `false` at all four tested widths.
