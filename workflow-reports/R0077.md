## B — Changes Applied

### B1 — `artifacts/pack-checklist/index.html`
- Removed `maximum-scale=1` from `<meta name="viewport">`.  
  Rationale: restricts browser zoom to ≤100%, blocking WCAG 1.4.4 (Resize Text) compliance.

### B2 — Color contrast (`MobileFunctionalV3.tsx` constants)
| Token | Before | After | Before ratio | After ratio |
|-------|--------|-------|-------------|-------------|
| `MUTED` | `#9AAA9F` | `#667270` | 2.43:1 ❌ | **4.99:1** ✅ |
| `NAV_INACTIVE` | `#A0ADA8` | `#6E7672` | 2.32:1 ❌ | **4.67:1** ✅ |

All other palette tokens (`PRIMARY`, `SECONDARY`, `NAV_ACTIVE`) were already compliant.

### B3 — CSS focus-visible rule (style block in JSX)
Added:
```css
.tw-v3-root input:focus-visible,
.tw-v3-root select:focus-visible,
.tw-v3-root textarea:focus-visible {
  outline: 2px solid #2A5740 !important;
  outline-offset: 1px !important;
}
```
Restores focus rings on inputs that had `outline:'none'` suppressed inline.  
The inline `outline:'none'` props were also removed from the Add Category input and Rename input.

### B4 — Item row restructure (R0077's most complex change)
**Before:** A single `div[role="button"]` containing a `div[role="checkbox"]` child — an interactive-inside-interactive WCAG failure. The inner checkbox had `tabIndex={-1}` making it keyboard-unreachable.

**After:** Split into two independent controls with no nesting:
1. **`<button role="checkbox" tabIndex={0}>`** — 44×44px hit area (width:44, minHeight:44 from container), contains 20×20 visual artwork. Keyboard: Space/Enter toggles checklist inclusion.
2. **`div[role="button" tabIndex={0}]`** — `flex:1` width, `minHeight:44`. Keyboard: Space/Enter expands item detail panel.

The outer wrapper is a plain layout div (`display:flex, alignItems:stretch, minHeight:44`), carrying no interactive role.

## I — Key Implementation Decisions

1. **Item row split**: Changed from single `div[role="button"]` with nested `div[role="checkbox"]` to two sibling controls. This is the architecturally correct fix for interactive-inside-interactive violations. The expand button remains a `div[role="button"]` (not `<button>`) consistent with existing patterns for custom keyboard handling.

2. **Category header target area**: The category options button achieves 44px height without expanding the header by containing both name and subtitle inside it (64px total < CARD_H 68px). This preserves R0076P2 J01 alignment.

3. **CardDeck close button**: Visual circle stays 28×28 (matches design); transparent button container is 44×44. The `background:'none'` on the outer button preserves the appearance.

4. **Color choices**: MUTED `#9AAA9F→#667270` (2.43→4.99:1) and NAV_INACTIVE `#A0ADA8→#6E7672` (2.32→4.67:1) use minimum darkening to pass AA 4.5:1 with minimal visual disruption.

5. **SwipeDeleteRow scroll reset in A04**: The bounded item viewport scrollTop was already at 65px (max) after adding 8 items. The test resets it to 0 before the CDP touch drag to ensure measurable scrolling.

6. **A14 delete trigger**: `evaluate(el => el.click())` bypasses Playwright's pointer simulation (which could be intercepted by SwipeDeleteRow pointer handlers) while still triggering React's root-level synthetic event listener.
