## Defect 1 — Touch scroll escapes bounded item viewport

### Symptom
When a long-mode category (≥ N items, bounded inner scroll viewport active) is open,
placing a finger on the item rows and performing a vertical drag scrolled the **outer
category stack** instead of (or in addition to) the bounded item viewport.

### Root Cause
In the `openCatName` alignment `useEffect`, `raf1` set:

```ts
ms.style.overflowY = 'auto';   // ← R0076P3 Defect 1 root cause
```

This was intended to temporarily unlock the outer scroll so that `ms.scrollTop`
could be adjusted to align the category header under the List Summary bar.  
However, assigning `scrollTop` programmatically is **valid on `overflow: hidden`
elements** — the spec allows it (MDN confirms).  The `overflowY = 'auto'` assignment
was therefore unnecessary.

When `isCatLong` was **already `true`** (the category entered long mode on a prior
alignment run), `remeasureLongMode()` called in `raf2` called `setIsCatLong(true)` —
a no-op.  React did **not re-render** the component.  Without a re-render, the React
style prop `overflowY: 'hidden'` (line 3207) was never reapplied.  The **inline DOM
override persisted permanently**, leaving `main-scroll` natively scrollable by touch
for the rest of the session.

### Fix
Removed the `ms.style.overflowY = 'auto'` line from `raf1`.  The alignment logic
`ms.scrollTop = target` now runs directly on the hidden-overflow element — no unlock
needed, no permanent DOM override.

Additionally, added `overscrollBehavior: 'contain' as const` to the bounded item
viewport's inline style (applied only in long mode).  This prevents the browser from
chaining a scroll gesture from the inner viewport to the outer scroll when the inner
viewport reaches its top or bottom boundary.

## Defect 2 — Item accordion allows multiple panels open

### Symptom
Opening item B while item A was expanded left both panels visible simultaneously.

### Root Cause (Analysis)
Code investigation confirmed the single-global-`expandedItem` state pattern is
logically correct:

```ts
const isExpanded = expandedItem?.cat === catName && expandedItem?.id === item.id;
```

Only one `{ cat, id }` pair can match at a time.  Item panels are rendered with
`{isExpanded && <detail-panel>}` — a falsy `isExpanded` immediately unmounts the
panel from the DOM.

The live-device failure was caused by **Defect 1**.  With `main-scroll` remaining
natively scrollable during long mode, touch gesture events intended to tap item B
were partially consumed by the outer scroll (which shifted the DOM), causing the
click to land on an unintended element.  From the user's perspective the result
appeared as two panels simultaneously open.

### Fix
Fixing Defect 1 (locking `main-scroll`) removes the gesture interference.
Adding `overscrollBehavior: 'contain'` to the inner viewport prevents any residual
scroll chaining.  After both changes, P3-05 through P3-09 confirm correct
single-open behavior under simulated touch conditions.

_(same as Defect 1 — no additional code changes required)_

## Key Implementation Notes

1. **`overflow: hidden` elements accept `scrollTop` assignment** — the DOM spec
   guarantees programmatic `scrollTop` works regardless of CSS overflow value.
   User gestures are blocked; JS assignments are not.  Removing the `overflowY`
   unlock is therefore safe and removes the sole leak vector.

2. **CDP `Input.dispatchTouchEvent` for real scrolling** — tests P3-01 through P3-03
   use Chrome DevTools Protocol to dispatch `touchStart / touchMove / touchEnd`
   events through the browser's input pipeline.  DOM-dispatched fake `TouchEvent`
   objects do NOT trigger native browser scrolling; CDP events do.

3. **`overscrollBehavior: contain` on inner viewport** — applied only in long mode.
   Prevents gesture chaining from the bounded inner scroll to the outer `main-scroll`
   at boundary conditions (inner `scrollTop = 0` or `scrollTop = max`).

4. **Single-open accordion was code-correct** — no state or rendering change was
   required for Defect 2.  The root cause was Defect 1's DOM override causing
   gesture misrouting.
