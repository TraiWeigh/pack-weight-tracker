## Summary of Changes in Correction Pass

### 1. PackLocation — photoDataUrl property

`PackLocation` type extended with `photoDataUrl?: string`. A location photo is a compressed JPEG owned by TrailWeigh (not the device file). Shared by every item linked to that location. Deleting/changing it never affects item photos or the device original.

### 2. Narrowed Auto-switch to Edit Group

Previously `mutateSandbox` always called `navGroupRef.current?.switchGroup(1)` on any mutation. This caused check/uncheck, add item, delete item, add category, delete category to incorrectly surface the Edit nav group.

**Fix:** Split into two functions:
- `mutateSandbox` — records undo/redo only; no nav switch
- `mutateSandboxEdit` — calls `mutateSandbox` then `switchGroup(1)`

**Callers using `mutateSandboxEdit` (edit-class):** rename item/category/location, weight change, qty change, move item, reorder categories, location assign/change/rename, photo add/change/delete.

**Callers using plain `mutateSandbox` (non-edit):** check/uncheck, add item, delete item, add category, delete category, add/remove location infrastructure, locker load, reset.

`updateItem` accepts an optional `{ edit?: boolean }` flag to select which function is used internally.

### 3. Location View — Wedge-based Hybrid (replaces flat list)

**Old:** `viewMode === 'location'` hid the catListRef div and rendered a flat `[data-testid="location-view"]` block with grouped header rows.

**New:** catListRef div always renders. In Location view:
- Category wedges show only their **unlocated** items (items with a `locationId` are suppressed from their category wedge)
- After catListRef, **Location wedges** render for each used location — visually identical to category bars:
  - Wedge button uses MapPin icon with NAV_ACTIVE background
  - Left slot: fixed text "**Location**" (where category name normally shows)
  - Right slot: the actual location name (e.g. "Bear Canister")
  - Subtitle: item count
  - Pencil button → opens Location Rename dialog
  - Trash button → deletes location (unlinks all items)
  - One-open-at-a-time: opening a location closes any open category and vice versa
- Each open Location wedge shows: Location Photo row, inline photo viewer, item rows (with "Edit" button to jump to category view)
- Data testids: `loc-wedge-{id}`, `loc-header-{id}`, `loc-photo-add-btn`, `loc-photo-view-btn`, `loc-photo-edit-btn`, `loc-photo-view-close`

### 4. Change Location → Dropdown (replaces picker sheet)

**Old:** "No location" button opened a `[data-testid="location-picker-sheet"]` with filter input, list of locations, and create/assign flows.

**New:** Native `<select data-testid="item-location-select">` inside the item accordion Location row:
- Shows `"No location"` (value `""`) when unassigned
- Lists all saved locations by name
- Has `"— Create New Location… —"` (value `__create__`) at the bottom
- Selecting an existing location calls `setItemLocation` (which uses `mutateSandboxEdit`)
- Selecting `__create__` opens a **Create New Location dialog** (`[data-testid="create-location-dialog"]`) with name input + Save/Cancel

**Location Rename** is now accessible only from the pencil button on the Location wedge bar → opens `[data-testid="location-rename-dialog"]` with same bottom-sheet style as item rename.

### 5. Location Photo

- `PackLocation.photoDataUrl?: string` — compressed JPEG
- In an open Location wedge: "Add Photo" button or "View Photo" / "Edit Photo" buttons
- `loc-photo-add-btn` → opens `[data-testid="loc-photo-edit-sheet"]`
- Inline viewer: `loc-photo-view-btn`, `loc-photo-view-close`
- Separate file inputs: `locCameraRef`, `locUploadRef`
- Handlers: `handleLocPhotoAdd`, `handleLocPhotoDelete` — both use `mutateSandboxEdit`

### 6. Item Photo Button Labels

- `"View"` → `"View Photo"` (when photo is present)
- `"Hide"` → `"Hide Photo"` (when inline viewer is open)
- `"Edit"` → `"Edit Photo"`
- Behavior unchanged
