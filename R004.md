## Part 1 — Slide-to-Delete

| Requirement | Implementation |
|---|---|
| Right-edge start | Gesture must begin within the right 40% of the row; starts elsewhere are ignored (verified by test) |
| Row follows finger | Content translates with the pointer, clamped to [-88px, 0]; no overshoot |
| Red Delete underneath, right | Absolutely positioned 88px action (#B03A2E) beneath the row content |
| Horizontal vs vertical disambiguation | 8px slop, then mode lock: mostly-vertical → native scroll (`touch-action: pan-y`), reveal never opens |
| Settle open/closed, no bounce | Past half the action width → open; otherwise closed; 0.18s ease-out, no spring |
| Swipe never deletes | Reveal tap routes into the EXISTING confirmation surfaces: category → Category Options delete confirm; item → "Delete \"name\"?" dialog |
| One reveal at a time | Single `openSwipe` state key; opening another row, scrolling, tapping elsewhere, opening a deck, or starting a reorder closes it |
| Resting trash icons removed | Item-row trash button removed (no reserved space left); category headers never had one |
| Accessible non-swipe paths | Category: name tap → Category Options sheet → Delete (pre-existing). Item: new "Delete Item" row in the expanded detail panel (keyboard focusable, `aria-label="Delete <name>"`) |
| Post-drag click swallowed | The synthetic click that follows a horizontal drag is consumed so it cannot immediately re-close/activate |

## Part 2 — Category Reorder

- Floating styling is keyed by category NAME, not array index — after crossing positions the elevation stays on the actually-dragged category (`data-floating` asserted in tests).
- Raised state: elevated shadow, slight scale (1.015), full opacity, z-index above siblings; a restrained translateY lean (±22px) keeps the card visually attached to the finger between slot swaps.
- Exactly one valid target dims (opacity 0.55, `data-dimtarget`) — computed against the stable original order (the category being displaced by the current destination), so the dim persists correctly while crossing; it undims the instant the floating card returns to its own slot or moves to a different target (both asserted).
- Release: order commits (or reverts if unchanged), ALL effects clear immediately (asserted: zero floating/dim nodes after release).
- Cancellation: `pointercancel` / `lostpointercapture` route through an idempotent cancel path that clears every drag effect and does NOT commit a reorder (asserted with a dispatched `pointercancel`).
- Coexistence: starting a reorder closes any open delete reveal; a horizontal swipe cannot start a reorder (reorder initiates only from the six-dot grip, which uses `touch-action: none` and stops propagation).
