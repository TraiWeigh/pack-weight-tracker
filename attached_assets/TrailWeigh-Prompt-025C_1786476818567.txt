PRIMARY USER REQUEST

In the Scan Gear List IMPORT PREVIEW:

TYPE and NAME are currently editable.

They should NOT be editable.

The preview should be a review/correction step, not a second full list editor.

REQUIRED PREVIEW BEHAVIOR

For DETECTED / IMPORTED rows shown in Scan Gear List preview:

CATEGORY
- remains adjustable/editable as it is now.

TYPE
- becomes READ-ONLY / DISPLAY-ONLY.
- user must not be able to type into it.
- user must not be able to erase or overwrite it.
- it should display the detected Type clearly.

NAME
- becomes READ-ONLY / DISPLAY-ONLY.
- user must not be able to type into it.
- user must not be able to erase or overwrite it.
- it should display the detected Name clearly.
- blank Name should remain visibly blank or use the existing subtle placeholder treatment, but must not become an editable input.

WEIGHT
- remains editable as it is now.
- preserve unit controls and validation.

QTY
- remains editable as it is now.

CHECKBOX / SELECTION
- preserve current behavior.

IMPORT BUTTON
- preserve current behavior.

CATEGORY ADJUSTMENT
- preserve current behavior.

AFTER IMPORT — MAIN TRAILWEIGH LIST

IMPORTANT:
Do NOT make Type or Name read-only in the main TrailWeigh list.

After the user imports items into the main list:
- Type remains editable exactly as it is now.
- Name remains editable exactly as it is now.

This prompt changes ONLY the Scan Gear List preview.

VISUAL REQUIREMENT

TYPE and NAME should look like normal readable table values, not disabled form controls.

Preferred appearance:
- plain text/display text inside the existing cell;
- same normal text color as other readable values;
- no gray "disabled" haze;
- no obvious input box border/background;
- preserve truncation/ellipsis behavior where needed;
- preserve horizontal scrolling and column alignment.

The user should visually understand:
"This is what TrailWeigh detected."

Do not make the values look unavailable or broken.

ACCESSIBILITY / KEYBOARD

Because Type and Name are no longer editable:
- they should not receive text-input focus;
- Tab navigation should skip any removed Type/Name text inputs;
- Category, Weight, Qty, checkboxes, Import, Add Row, Cancel, and other actual controls should remain keyboard reachable;
- preserve useful accessible labels for the row/cells.

Do not remove text selection/copying if plain text naturally allows it.

IMPORTANT — ADD ROW

Do NOT redesign or remove the existing “+ Add Row” feature in this prompt.

The user request is specifically about detected/imported preview rows.

If Add Row creates a special manual row that technically requires Type/Name entry:
- preserve the existing Add Row behavior for that MANUALLY ADDED row only;
- do not use that exception to keep Type/Name editable on detected/imported rows.

In other words:

DETECTED / IMPORTED ROW:
Type = read-only
Name = read-only

MANUALLY ADDED ROW VIA “+ Add Row”:
May retain its existing Type/Name entry behavior if required for the feature to remain usable.

Do not broaden this prompt into an Add Row redesign.
