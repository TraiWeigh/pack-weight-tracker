4. LONG MANUALLY OPENED CATEGORY — AUTO-POSITION
============================================================

When a manually opened category does not fully fit between List Summary and the bottom box bar:

- automatically reposition/scroll that category upward enough to maximize visible items
- the TOP of the category header may move upward only until it reaches the hard upper stop
- HARD UPPER STOP = bottom edge of the List Summary bar
- the category header must never move under/behind the List Summary
- when this long-category behavior is active, the Add Item bar should rest directly above the bottom box bar with no wasted blank strip
- do not cover the bottom box bar
- do not move the app shell
- do not create horizontal overflow
- do not break category reorder, slide-delete, vertical scrolling, or bottom box-group sliding

Use existing scroll/layout ownership where possible. Avoid a new nested-scroll architecture unless absolutely necessary.

============================================================
5. IF THE CATEGORY IS STILL TOO TALL
============================================================

If the category remains taller than the available region after its header reaches the hard upper stop:

- keep the category header at/below the List Summary boundary
- keep the Add Item bar available at the bottom of the visible category region, directly above the bottom box bar
- allow the item content to move through the available window using the existing safe scroll model
- do not move the Add Item bar off-screen while overflow navigation is active
- maximize visible items first; use scrolling/navigation only when content genuinely cannot fit

Do not claim scrolling is unnecessary when the content is physically taller than the available area.

============================================================
6. ADD ITEM BAR — ONE RIGHT-SIDE OVERFLOW CHEVRON
============================================================

Add ONE directional chevron on the RIGHT side of the contextual Add Item bar.

Chevron state:
- hidden content BELOW -> chevron points DOWN
- hidden content ABOVE and none below -> chevron points UP
- if both above and below are possible, use one chevron only:
  while later content remains below, point DOWN;
  once the bottom is reached, change to UP
- no overflow -> chevron hidden or clearly disabled

Tap behavior:
- DOWN -> smoothly advance item content by about one visible-page increment
- UP -> smoothly move item content upward by about one visible-page increment
- do not jump end-to-end unless one page naturally reaches the end
- no spring/bounce animation
- manual vertical scrolling remains available
- chevron state must update after manual scrolling

Accessibility:
- DOWN: "Show later items"
- UP: "Show earlier items"

============================================================
7. LIST SUMMARY — ONE GLOBAL EXPAND/COLLAPSE CHEVRON
============================================================

Add ONE chevron only inside List Summary.

Exact placement:
- horizontally in the open space BETWEEN:
  left = item-count block (example "80 items")
  right = Selected block / circled checkmark
- not at the far edge
- not on the bottom border as a separate tab

Exact vertical position:
- align with the large item-count number ("80")
- use the SAME bottom padding from the List Summary bar as the "80"
- do not center vertically in the whole panel if that changes this alignment

Size/style:
- approximately the visual size of the large "80"
- generous touch target
- visible but subdued
- no heavy button chrome
- no second chevron

============================================================
8. LIST SUMMARY CHEVRON — STATE AND ACTION
============================================================

ONE CHEVRON ONLY.

All categories collapsed:
- points DOWN
- accessible name: "Expand all categories"

One or more categories expanded:
- points UP
- accessible name: "Collapse all categories"

Tap DOWN:
- EXPAND ALL categories

Tap UP:
- COLLAPSE ALL categories

Drive the icon from REAL accordion open state. Do not use a separate boolean that can drift out of sync.

Do not re-add Expand All / Collapse All in More or another control area.

- every expanded category still has its own Add Item bar at the end of its item list
- normal parent list scrolling remains available

When categories are collapsed and the user manually opens one category:
- apply the focused category viewport behavior in Sections 4–6
