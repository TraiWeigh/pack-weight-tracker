The custom-theme delete warning is STILL appearing at the bottom of the Themes
panel/page.

The user wants the delete warning to appear directly NEXT TO the custom-theme
trash icon, matching the same local/anchored delete-confirmation pattern used
on the category bar.

Treat the prior delete-warning positioning work as FAILED for this requirement.

THIS PROMPT IS FOCUSED ONLY ON THE CUSTOM-THEME DELETE CONFIRMATION POSITION.

Do NOT redesign the Background Themes system.
Do NOT change the underlying delete logic unless required to preserve the
existing delete action.

1. REQUIRED RESULT
==================================================

When the user taps/clicks the trash icon for a CUSTOM THEME:

The delete confirmation must open as a SMALL ANCHORED CONFIRMATION POPOVER
directly next to the trash icon.

It must NOT appear:
- at the bottom of the Themes panel
- at the bottom of the page
- as a detached document-flow warning
- far away from the trash icon
- behind other content

The trash icon is the trigger and the warning must remain visually associated
with that trigger.

==================================================
2. MATCH THE CATEGORY-BAR DELETE PATTERN
==================================================

Inspect the existing category-bar delete confirmation.

Use the SAME general interaction pattern where practical.

Preferred:
- reuse the same component
OR
- reuse the same positioning logic
OR
- use the same Popover primitive

Do not invent a second unrelated confirmation system if the category-bar
pattern already works.

The custom-theme delete warning should feel like the same product behavior.

==================================================
3. ANCHORED POSITIONING
==================================================

Anchor the popover to the custom-theme trash button.

Preferred placement:

- beside the trash icon
- or slightly below/above it if necessary for available space

Use collision-aware positioning.

The popover should:
- stay close to the trash icon
- remain fully inside the viewport
- flip above/below/left/right when necessary
- not be clipped by parent containers
- not create horizontal page overflow

If the Themes panel has overflow clipping, use an appropriate portal-based
popover approach so the confirmation can escape the clipping container while
remaining anchored to the trash icon.

==================================================
4. DO NOT RENDER THE WARNING IN NORMAL DOCUMENT FLOW
==================================================

The delete warning must NOT occupy a permanent block at the bottom of the
Themes panel.

Do NOT solve this with:
- conditional JSX appended after the theme list
- a bottom warning section
- extra bottom margin
- scroll-to-warning behavior

This confirmation belongs to the TRIGGER, not to the bottom of the panel.

7. DELETE
==================================================

Delete Theme must:

- call the EXISTING correct custom-theme delete action
- delete only the selected custom theme
- preserve all existing safety/fallback behavior
- close the popover after successful deletion
- not leave a ghost warning at the bottom of the panel

Do not rewrite deletion architecture unless needed for a bug found during
inspection.

==================================================

Do not render multiple detached warnings.
