CURRENT BASELINE
R0095 established the preferred mobile-shell architecture:
- AppBar outside normal scrolling
- List Summary outside normal scrolling
- checklist/category content owns the middle scroll
- Bottom Box Groups outside normal scrolling
- document/body should not own ordinary checklist scrolling

R0096 must preserve that architecture.

Do NOT revert to whole-document scrolling.

PRIMARY USER REQUIREMENTS

1. NEW LOCKED FILTER CONTROL
Replace the future Category / Location / Photo segmented concept with ONE Filter control.

The Filter control must:
- sit directly beneath the fixed List Summary;
- remain locked in place;
- not scroll with checklist/category content;
- open a menu/sheet of view/filter choices;
- initially include:
  - Category
  - Location
  - Photo
- be extensible later for more filters without changing the top-bar width.

Do not make the Filter control a separate full screen.

The selected option may be shown in the control in a compact way, for example:
- Filter: Category
or equivalent existing TrailWeigh visual language.

Do not over-design.

2. FILTER BAR LOCKING
Normal checklist structure should be:

LOCKED TOP
- AppBar
- List Summary
- Filter control/bar

SCROLLING MIDDLE
- checklist/category content

LOCKED BOTTOM
- Bottom Box Groups

The Filter control must remain physically stationary when the checklist scrolls.

3. CATEGORY HEADER LOCKING IN EXPANDED / OVER-EXPANDED STATE
When a category is opened far enough that its item content becomes the active working region:

- the active Category bar/header must be locked directly beneath the List Summary;
- it must not scroll away;
- it should occupy the same top-control slot used by the Filter bar;
- do NOT stack Filter + Category bar and waste vertical space.

Preferred behavior:
NORMAL LIST
List Summary
→ Filter bar
→ scrolling categories

ACTIVE / OVER-EXPANDED CATEGORY
List Summary
→ active Category bar
→ scrolling items/content

When category view closes/returns:
- Filter bar returns.

4. LOCKED ADD ITEM BAR FOR OVER-EXPANDED CATEGORY
When the active category is over-expanded / using its bounded item-content mode:

- Add Item bar must lock directly ABOVE the Bottom Box Groups;
- Add Item bar must not scroll with item content;
- only the item region between active Category bar and Add Item bar scrolls;
- Bottom Box Groups stays locked below Add Item.

Structure:

LOCKED TOP
- AppBar
- List Summary
- active Category bar

SCROLLING MIDDLE
- category items/content

LOCKED BOTTOM
- Add Item bar
- Bottom Box Groups

Preserve the existing Add Item function and appearance unless a tiny structural wrapper change is required.

5. HAMBURGER PANEL LOCK
The hamburger panel currently moves when the underlying page/content scrolls.

Fix this.

When hamburger panel is open:
- panel FRAME stays locked to the screen;
- panel must not move up/down with checklist scrolling;
- underlying checklist should not drag the panel;
- preserve current panel size, appearance, controls, and open/close behavior.

If hamburger panel content is taller than available screen height:
- only the INSIDE of the panel may scroll;
- panel frame remains stationary.

Do not redesign the hamburger menu.

6. PHOTO FILTER MODE — PRESERVE DEFINED BEHAVIOR
The new Filter menu includes Photo.

Photo mode is a VIEW MODE, not a separate screen.

When Photo mode is active and a category accordion is opened:
- items with photos show the photo in place of normal item accordion content;
- each item still retains its checkbox;
- items without photos may remain in normal form rather than disappearing;
- bottom of each displayed photo has only:
  - Delete
  - Edit
- NO separate Camera button;
- Delete removes the current item photo, with confirmation if current UI conventions support it;
- Edit offers:
  - Take New Photo
  - Choose from Photo Library
- replacing/taking a photo changes the photo only, not the underlying item;
- photo remains associated with that specific item;
- switching Photo mode off restores normal item presentation.

IMPORTANT:
If Photo mode implementation would materially broaden R0096 beyond a safe scope, implement the Filter infrastructure and wire Photo as a selectable placeholder/view-state only, then document Photo rendering as NOT YET IMPLEMENTED.

Do not force a risky full photo feature into this task merely because the Filter control exposes the option.
