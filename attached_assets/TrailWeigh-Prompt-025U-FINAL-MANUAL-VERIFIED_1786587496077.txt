OFFICIAL REPLIT PLATFORM BASELINE — DO NOT RE-LITIGATE WITHOUT
PROJECT-SPECIFIC CONTRARY EVIDENCE
============================================================

Treat the following as the current official Replit platform baseline:

A. PLAN MODE
- Plan mode reads the project and answers/plans without modifying project files.
- It is intended for questions, architecture, tradeoffs, and planning.
- Plan mode is still billable.

B. BUILD MODE
- Build mode can write/modify project files and implement changes.

C. TASKS
- Background tasks execute in isolated copies of the project.
- A Ready background task does not affect the main version until changes are applied.
- "Apply changes to main version" merges the task work into main.
- Auto-apply exists and can bypass the normal manual review step if selected.

D. CONTEXT
- Long/noisy conversations can cause old or irrelevant context to interfere.
- Replit recommends a fresh thread when old constraints keep leaking in.
- Important retained context should be summarized into the fresh thread.
- `replit.md` is official persistent project context and Agent reads it automatically.
- Replit documentation says Agent can update `replit.md`.

E. CHECKPOINTS / ROLLBACK
- Checkpoints capture project state and database checkpoint state.
- Ordinary rollback restores project state.
- Development database rollback is OPTIONAL and occurs when Database is selected
  in Additional rollback options.
- Production database is not automatically restored by ordinary project rollback.

F. DATABASE ENVIRONMENTS
- Current Replit database infrastructure uses separate Development and Production DBs.
- Current development DB infrastructure is Helium.
- Legacy Neon projects are an exception and must be identified explicitly.
- The current manuals explain that `DATABASE_URL` containing `neon.tech` means legacy
  Neon; current infrastructure is identifiable as Helium.
- Publishing creates/uses a Production database separate from Development on current
  infrastructure.
- Agent cannot directly modify the Production database through normal development Agent work.

G. APP TESTING
- App Testing uses a real browser.
- App Testing can identify problems AND automatically fix issues it finds.
- Therefore App Testing is NOT appropriate for this no-change diagnostic unless
  explicitly authorized.

H. PREVIEW DEVTOOLS
- Preview Devtools can inspect console, DOM, network, localStorage,
  sessionStorage, and cookies.
- Preview Devtools also contain destructive clear/delete controls.
- This prompt authorizes READ-ONLY inspection only.

I. COST
- Replit Agent uses effort-based billing.
- Long/complex context can cost more.
- Economy is the cost-conscious default.
- Focused evidence requests are preferred to broad repeated rereads.

J. SECURITY
- Replit now performs automatic security checks on files Agent changes during builds.
- A full Security Agent scan is a separate capability and is not a replacement for
  application-specific security verification.

If current project evidence genuinely contradicts any baseline above:
