==================================================
1. REQUIRED DEFAULT PANEL STATE
==================================================

TrailWeigh should NOT start with every panel closed.

The desired startup state is:

SIGNED-IN / PRIVATE CHECKLIST

OPEN BY DEFAULT:
- Scan Gear List
- Locker

CLOSED BY DEFAULT:
- All gear-category panels
- Pack Summary
- Weight Distribution
- Temporary menus/popovers
- Background picker/editor panel
- Preview/modal/dialog UI
- Other temporary UI

FULL SHARED TRAILWEIGH LINK

OPEN BY DEFAULT:
- Scan Gear List
- Shared Files

CLOSED BY DEFAULT:
- All gear-category panels
- Pack Summary
- Weight Distribution, once present
- Temporary menus/popovers
- Background picker/editor panel
- Preview/modal/dialog UI
- Other temporary UI

This is the intended design.

==================================================
2. TERMINOLOGY — LOCKER VS SHARED FILES
==================================================

On the signed-in/private Checklist, the user's personal saved-file area is the:

Locker

On the Shared Link, the equivalent browsing panel currently displayed to the viewer is:

Shared Files

Do not rename these controls merely to make their labels identical.

The requirement is:

PRIVATE:
Locker starts OPEN.

SHARED:
Shared Files starts OPEN.

==================================================
3. SCAN GEAR LIST STARTS OPEN
==================================================

Scan Gear List should start OPEN in BOTH:

- Signed-in/private Checklist
- Full Shared TrailWeigh Link

When TrailWeigh is opened, refreshed, or reinitialized:

Scan Gear List should be expanded and its content immediately visible.

The user can still manually collapse it.

During the current session:

- If the user collapses it, leave it collapsed.
- Do not continually force it back open.

On the next page initialization/refresh:

- Return it to its intended default OPEN state.

Do not change:
- Import behavior
- Supported file types
- OCR/import logic
- Item-selection behavior

==================================================

==================================================

On the signed-in/private Checklist:

Locker should start OPEN.

The user should immediately be able to see/access their saved lists without first opening the panel.

Preserve all current Locker functions and permissions.

Do not change:
- Save

- Open
- Rename
- Delete
- File IDs
- Account isolation
- Saved-file behavior

The user may manually collapse Locker during the current session.

On a new initialization/reopen/refresh, return it to OPEN.

==================================================

This must work consistently from:

- Signed-in/private Checklist
- Full Shared TrailWeigh Link

14. SAFARI NATIVE SHARE SHEET
==================================================

On Safari, the native Share sheet may provide options such as:

- Messages
- Mail
- AirDrop
- Copy
- Other installed/system destinations

TrailWeigh must allow Safari/macOS/iOS to provide those choices.

Do NOT manually reproduce Safari's native Share sheet.

==================================================
15. SAFARI "SHARE ANYWAY" WARNING
==================================================

Safari may first display a browser-controlled:

Share Anyway

warning.

This is normal browser/security behavior.

TrailWeigh must NOT:

- Suppress it
- Bypass it
- Automatically confirm it
- Fake its own version
- Replace it

If Safari displays the warning:

1. Safari shows the warning.
2. The user chooses whether to continue.
3. If the user selects Share Anyway, Safari proceeds to its native Share sheet.

TrailWeigh should simply initiate the native sharing request correctly.

Do not refactor unrelated code.

- Expose private Locker information

21. DOWNLOAD PDF
==================================================

Preserve:

Share
  - Share TrailWeigh List → native Share sheet
  - Share Checkable Packing List → native Share sheet

Download PDF should NOT automatically invoke the native Share sheet as part of this prompt.

==================================================
22. DO NOT CONTROL EXTERNAL SAFARI WINDOW/TAB BEHAVIOR
==================================================

When a TrailWeigh link is tapped from:

- Messages
- Mail
- Notes
- Another application

Safari/macOS/iOS controls whether it opens:

- In an existing window
- In a new tab
- In a new window

Do NOT attempt to override this with browser hacks.

Do NOT add:
- window.open hacks
- automatic window closing
- redirect loops
- opener manipulation
- target tricks intended to override Safari preferences

This behavior is outside TrailWeigh's reliable control.
