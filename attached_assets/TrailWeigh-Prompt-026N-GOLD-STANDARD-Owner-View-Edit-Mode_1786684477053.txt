USER DECISION — AUTHORITATIVE MODE BEHAVIOR
============================================================

The USER has decided:

1. SAVED OWNER LIST
   - A saved list opened from the universal Locker opens in VIEW mode by default.

2. NEW OWNER LIST
   - A brand-new list starts in EDIT mode because the user is building it.

3. VIEW MODE
   View mode is a SAFE checklist-use mode.

   The user MAY:
   - check/uncheck checklist boxes
   - expand/collapse main categories
   - use main-category Expand All / Collapse All
   - expand/collapse item detail sections if currently supported
   - print / preview
   - share
   - navigate
   - use existing non-structural display controls unless explicitly prohibited below
   - use current manual Save behavior

   The user MAY NOT structurally change list content.

4. EDIT MODE
   - A clear `Edit` control switches a saved owner list from View -> Edit.
   - While in Edit mode, the control becomes `Done`.
   - `Done` returns Edit -> View.
   - Switching modes MUST NOT itself save, discard, revert, or alter list data.

5. SAVE SEMANTICS
   - Current explicit Save / Save As behavior remains unchanged in 026N.
   - 026N does NOT implement checkbox autosave or cross-device sync.
   - If a user manually saves while in View, current checked state may be included exactly as today.
   - Saving does not force a mode change.

6. REOPEN SEMANTICS
   - Opening a saved owner list from Locker must enter View, even if the user had previously edited that list.
   - Starting `New` must enter Edit.
   - Do not persist View/Edit mode into the saved list payload.
