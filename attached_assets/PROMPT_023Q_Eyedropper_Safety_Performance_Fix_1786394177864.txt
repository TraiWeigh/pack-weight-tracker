==================================================
3. SEPARATE LIVE PREVIEW FROM FINAL COMMIT
==================================================

Use a two-phase pattern if current code does not already have one.

PHASE A — LIVE PREVIEW

While the native picker/eyedropper produces intermediate samples:

- update only lightweight preview state
- update only the active file/window
- keep the UI responsive
- do NOT create an Undo entry for every sample
- do NOT persist every sample
- do NOT broadcast every sample to other windows
- do NOT trigger Locker writes
- do NOT trigger backend/database/network writes
- do NOT serialize the complete file repeatedly
- do NOT alter other saved files

PHASE B — FINAL COMMIT

When the user finishes choosing the color:

- commit the final selected color to the active file's canonical working appearance state
- create at most ONE logical Undo/history entry
- persist only according to TrailWeigh's existing explicit Save behavior
- do not silently save the file merely because the picker closed
- preserve Prompt 023P file isolation

IMPORTANT:
The user must still explicitly Save the active file if they want the final appearance permanently written to that saved Locker file.

==================================================
4. DO NOT BREAK FILE PROTECTION FROM 023P
==================================================

Prompt 023P fixed appearance leakage between files.

That protection is mandatory.

During native color-picker sampling:

- File A may preview its own color
- File B must not change
- File B's saved record must not change
- a New unsaved file must not inherit File A's live color
- another tab/window with a different file must not receive File A's intermediate colors

After final color selection:

- the final color remains part of File A's current working state
- it is not persisted into File A's saved Locker record until explicit Save
- it never modifies File B

Test this directly.
