PRIMARY GOAL
When a CSV/XLSX source explicitly identifies an apparel/footwear/headwear item as worn, TrailWeigh must preserve that information and organize it as Clothing Worn instead of Clothing Packed.

This prompt is NOT a general category/routing redesign.

SUPPORTED EXPLICIT WORN SIGNALS
Use the existing CSV/XLSX import path and support clear, explicit Worn indicators such as:

A. Dedicated Worn column/header
Examples:
- Worn = TRUE
- Worn = true
- Worn = Yes
- Worn = yes
- Worn = 1
- Worn = worn

B. Status column/header
Examples:
- Status = worn
- Status = WORN

C. Category/Subcategory values
Examples:
- Worn
- Worn Gear
- Clothing Worn
- Subcategory = Worn

D. Notes/Description only when the wording is an explicit worn marker
Examples:
- "Worn item"
- "Worn while hiking"

Do NOT classify an item as worn merely because a note contains an unrelated word fragment or vague contextual wording.

ROUTING RULE
If an item is BOTH:
1. clearly apparel / footwear / headwear under TrailWeigh's existing clothing recognition, AND
2. explicitly marked worn by one of the supported signals above,

then route it to:
Clothing Worn

instead of:
Clothing Packed
or generic Clothing.

Examples that MUST work:
- Hiking Shirt + Worn TRUE -> Clothing Worn
- Trail Runners + Worn Yes -> Clothing Worn
- Sun Hat + Subcategory Worn -> Clothing Worn
- Sun Hat + Status worn -> Clothing Worn

IMPORTANT SAFETY / SCOPE RULE
Do NOT blindly send every item with a worn flag into Clothing Worn if it is not clothing/footwear/headwear.

If a source marks a non-clothing item as worn/carried, preserve the existing normal TrailWeigh routing unless the current application already has a separate established non-clothing worn mechanism.

Do NOT invent a new category or data model in this prompt.
