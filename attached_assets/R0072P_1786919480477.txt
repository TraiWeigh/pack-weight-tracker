6. DIAGNOSTIC B — STACKED BARS MUST NOT MOVE
============================================================

USER REQUIREMENT
Stacked bars are tap controls only.
They must NOT move, lift, float, follow the finger, dock, or activate because they were dragged.

IMPORTANT
Test a NON-OVERFLOWING deck because the current source may only enable "lift" mode when the deck does not overflow.

TEST B1 — MID-DRAG PHYSICAL MOVEMENT
1. Open a short/non-overflowing deck.
2. Identify an inactive stacked bar.
3. Record its bounding box and computed transform BEFORE interaction.
4. Pointer/touch down near the center.
5. Move upward approximately 70–100 px while keeping the pointer down.
6. WHILE STILL HELD:
   - record its bounding box
   - record computed transform
   - take a screenshot if useful

PASS
- bar itself has not moved relative to its stack
- no translate/lift transform
- no floating/lift visual state

FAIL
- bar moves upward/downward with the finger
- transform changes to physically lift it
- bar visibly floats

TEST B2 — DRAG MUST NOT ACTIVATE
1. Start from inactive stacked bar.
2. Drag upward farther than any existing activation threshold.
3. Release.
4. Verify that the dragged stacked bar did NOT become the active card solely because of the drag.

PASS
- order/active state unchanged after drag
- only a TAP activates the stacked bar

FAIL
- drag/release activates the stacked bar

TEST B3 — TAP STILL WORKS
Separately perform a normal tap on the same stacked bar.

PASS
- tap activates it normally

This distinguishes "do not drag" from "do not work."

EVIDENCE
Prefer one short Playwright video showing:
- upward drag
- whether bar moves
- release result
- normal tap result
