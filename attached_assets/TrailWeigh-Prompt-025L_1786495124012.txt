==================================================
WHY 025L EXISTS
==================================================

The current Share page has repeatedly drifted from Home.

Past work showed:
- 025J improved some width/toolbar geometry and added a file-name pill, but did not achieve visual parity.
- Replit could not reproduce the authenticated Home route during 025J yet edited anyway, so source comparison was incorrectly used as proof.
- 025K succeeded because the exact rendered root cause was identified: a portaled Background panel sat outside the `.screen-dark` theme scope, and one small targeted fix corrected the real component.

LESSON:
Do not keep repairing a duplicate Share UI.

The user has decided to replace the separate Share-view experience with ONE TrailWeigh UI that runs in two modes:
1. OWNER MODE
2. PUBLIC REVIEW MODE

The visual Checklist experience must come from the same core component path.

==================================================
CURRENT PRODUCT DECISION — SOURCE OF TRUTH
==================================================

OWNER MODE
- normal TrailWeigh account;
- authenticated persistence;
- private Locker;
- owner files remain private unless deliberately shared;
- normal owner Save/Delete/Rename behavior remains unchanged.

PUBLIC REVIEW MODE
- NO LOGIN REQUIRED;
- a reviewer opens a permanent public review/share link;
- TrailWeigh opens as a fully usable sandbox;
- the shared file is preinstalled in that sandbox;
- reviewer may edit, add, delete, rename, reorder, save locally, create new files, delete files, change quantities/weights/units, use themes, use Light/Dark, Preview, Hide, etc.;
- reviewer may freely experiment;
- reviewer actions NEVER modify the owner's original file;
- reviewer cannot access owner's private Locker, private files, account settings, or authenticated data.

The reviewer experience should feel like a normal installation of TrailWeigh with preinstalled files — not a restricted viewer.

==================================================
PERMANENT SERVER-SIDE SEED VS REVIEWER COPY
==================================================

Use a two-layer model:

PERMANENT PUBLIC READ-ONLY SEED
        ↓
REVIEWER SANDBOX COPY

The permanent seed contains only the file(s) intentionally assigned to that review link.

For the existing Share action:
- the currently active owner file may remain the seed file.

Do NOT publish the owner's entire Locker.

The reviewer sandbox copy is disposable and editable.

Reviewer may:
- rename it;
- modify it;
- delete it;
- create other files.

Deleting the reviewer copy must NOT:
- delete the owner's original;
- delete the permanent public seed;
- revoke the public share;
- affect another reviewer.

A fresh browser/device/private session should receive a fresh copy from the permanent seed.

For the SAME browser:
- preserve reviewer sandbox changes across refresh/reopen where practical;
- if reviewer deleted the preinstalled file, keep it deleted locally until local review data is reset/cleared;
- the server seed still remains available.

If practical with existing UI, add a small “Restore Preinstalled Files” or equivalent recovery action only if this can be done narrowly.
Do not redesign the app just for this.

==================================================
OWNER STORAGE VS REVIEW STORAGE
==================================================

Separate UI from persistence.

Conceptual design:

CORE CHECKLIST UI
      ↓
STORAGE / PERMISSION ADAPTER

OWNER ADAPTER
- existing authenticated persistence;
- existing private Locker;
- existing owner file Save/Delete/Rename behavior.

REVIEW ADAPTER
- reads permanent public seed;
- writes reviewer changes ONLY to the local review sandbox;
- never writes to owner records.

Prefer an existing TrailWeigh guest/local-storage abstraction if one already exists.

If none exists, use browser `localStorage` for NON-SENSITIVE reviewer sandbox data because it persists across browser sessions.

Requirements if `localStorage` is used:
- namespace keys by review token/link;
- never store owner credentials/auth tokens/secrets;
- catch quota/storage errors gracefully;
- do not crash if storage is unavailable;
- keep data structure versioned enough that future migrations can be handled safely.

Do not use cookies for storing review file payloads.

==================================================
SHARE CONTROL INSIDE REVIEW MODE
==================================================

Do not allow an anonymous reviewer to create server-side public shares of arbitrary local review content unless an existing safe anonymous-share path already explicitly supports it.

Safe default:
If Share remains visible in Review mode, it may simply copy/share the EXISTING review URL.

It must not imply that the reviewer's local edits were published.

Do not weaken server authorization to preserve this button.

==================================================
AUTHENTICATION / SECURITY
==================================================

Public Review mode intentionally has no login.

However, anonymous access must be limited to PUBLIC REVIEW SEED data.

Server/API authorization must prevent a reviewer from:
- modifying owner original file;
- deleting owner original file;
- renaming owner original file;
- reading owner Locker;
- enumerating owner private files;
- accessing another private object by changing an ID/token;
- changing owner account settings;
- writing to authenticated owner endpoints.

Do not rely on hidden buttons alone.

Apply least privilege / deny-by-default to owner resources.

The public route/API may return only data intentionally included in the public review seed.

==================================================
IMPORT / OCR / EXPENSIVE SERVER FEATURES
==================================================

Do not silently expose privileged or expensive endpoints anonymously.

If Scan Gear List / OCR / import already works safely in anonymous mode, preserve it.

If it requires authenticated privileged server access:
- do not weaken security;
- document the limitation;
- STOP before broadening endpoint permissions.

This prompt is about the core public review architecture, not opening every server feature anonymously.
