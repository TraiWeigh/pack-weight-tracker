PRIMARY PROBLEM

Some users make Word packing lists with no tables.

A common structure is:

Backpack
• Backpack - Durston Kakwa 55 - 30.1 oz

Shelter
• Tent - Zpacks Duplex - 18.5 oz

Kitchen
• Stove - BRS-3000T - 0.9 oz
• Fuel Canister - 3.9 oz - Qty 2

The category is supplied by the heading.
Each gear item is a bullet paragraph.

TrailWeigh should be able to import this simple structure.

PRIMARY GOAL

For DOCX import only:

When a valid DOCX category context has already been established by the existing heading logic, recognize compatible bullet/list paragraphs beneath that category as gear items.

Support this compact bullet syntax:

TYPE - NAME - WEIGHT

or, when Name is absent:

TYPE - WEIGHT

Optional quantity:

TYPE - NAME - WEIGHT - Qty N

or:

TYPE - WEIGHT - Qty N

The supplied test uses ASCII space-hyphen-space:

" - "

as the separator.

You may safely normalize equivalent spaced separators such as:
- " – "
- " — "

if that is trivial and does not broaden parsing risk.

Do NOT split on every hyphen character.

IMPORTANT:
Product names such as:
- Therm-a-Rest
- BRS-3000T

contain internal hyphens.

Only spaced separator tokens should separate bullet fields.

BULLET ITEM RECOGNITION — CONSERVATIVE

A DOCX bullet/list paragraph should become a gear item only when it has enough structured evidence.

For this prompt, require at minimum:

1. It is structurally a Word list/bullet item or is emitted by the DOCX converter as a list item.
2. A current category context exists.
3. The text contains a parseable gear weight using the existing TrailWeigh weight parser.
4. A plausible Type segment exists before the weight.
5. The line matches the supported compact field structure.

This is important because:

• Remember permits
• Check weather before departure

have no parseable weight and must be ignored.

Do NOT treat every bullet as gear.

PARSING ORDER / SAFETY

Prefer parsing from recognizable right-side fields:

1. Detect optional trailing Qty segment.
2. Detect the weight segment using existing TrailWeigh weight parsing.
3. Remaining first segment = Type.
4. Remaining middle segment(s), if any = Name.

Do not infer Name from weight/spec/status text.

Do not invent Name.
