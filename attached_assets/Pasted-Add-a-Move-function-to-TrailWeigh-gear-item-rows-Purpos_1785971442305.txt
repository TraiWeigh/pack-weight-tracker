Add a Move function to TrailWeigh gear-item rows.

## Purpose

Users must be able to move an existing gear item from its current category into another existing category.

The move must preserve the complete item and must work with Undo and Redo.

Do not redesign unrelated checklist controls.

## Move control placement

On every normal gear-item row, add a control labeled:

Move

Place it between:

- Description
- Weight

The desktop row order should be:

1. Checkbox
2. Type
3. Description
4. Move
5. Weight
6. Unit
7. Quantity
8. Existing item controls

Use the existing TrailWeigh control style.

The Move control may be a compact dropdown or menu, but it must be easy to understand and use.

## Destination list

When Move is opened, list all current categories except the item’s current category.

Examples:

- An item in Backpack should not list Backpack as a destination.
- An item in Kitchen Gear may list Backpack, Shelter System, Sleep System, Clothing Packed, Electronics, and the other existing categories.
- User-created custom categories must also appear.
- Do not list deleted or hidden categories.
- Do not create a new category from the Move menu.

Use the exact category names and order from the current checklist.

Respect user-defined names and category aliases, including names such as:

- Shelter System
- Sleep System
- Kitchen Gear
- Cook Set
- Camp Kitchen

Do not rename the destination category.

## Move behavior

When the user selects a destination:

1. Remove the item from its current category.
2. Insert the same item into the selected destination category.
3. Do not leave a duplicate in the original category.
4. Do not create a second copy with a new ID unless the existing data architecture absolutely requires it.
5. Preserve the destination category’s existing items.
6. Keep the current category headings and order unchanged.

The item may be appended to the bottom of the destination category unless TrailWeigh already has a consistent insertion rule.

Do not automatically scroll the user away from their current position unless necessary.

## Preserve the complete item

Moving must preserve every available item property, including:

- Item ID
- Type
- Description
- Weight
- Weight unit
- Quantity
- Main checkbox state
- Expendable state
- Worn state
- Dog Pack state
- Base Weight inclusion state
- Any warning or validation state that belongs to the item
- Any other stored item metadata

Do not reset the item to unchecked merely because it was moved.

Imported items should still initially import unchecked, but a later Move must preserve their current checkbox state.

## Undo and Redo

Move must be a normal TrailWeigh history action.

After moving an item:

- Undo restores the item to its original category and original position when practical.
- Redo moves it back to the selected destination.
- One move should create one undo-history step.
- Undo and Redo must not duplicate or delete the item.
- Background Undo/Redo behavior must remain intact.
- Moving an item must not clear unrelated history unless the current architecture requires a documented reason.

Inspect the existing history implementation in:

- `artifacts/pack-checklist/src/hooks/usePackData.ts`
- `artifacts/pack-checklist/src/pages/Checklist.tsx`

Use the existing Store/history architecture rather than building a second history system.

## Working-list and saving behavior

Moving an item changes only the currently open working list.

It must not automatically save the file.

The user must still use Save or Save As to persist the moved item to the Locker.

Preserve:

- Active file identity
- Active filename
- Save
- Save As
- Locker behavior
- New-file behavior
- Same-tab and new-tab opening behavior

Do not alter another open tab’s unsaved working list.

## Data implementation

Inspect the current data model:

- Category order is stored in `store.order`
- Category items are stored in `store.items[category]`
- Gear item state is managed through `usePackData.ts`

Add one clear reusable operation such as:

`moveItem(sourceCategory, destinationCategory, itemId)`

or the equivalent appropriate to the current architecture.

The operation should:

1. Validate that the source and destination categories exist.
2. Validate that source and destination are different.
3. Find the item by stable ID.
4. Preserve the complete item object.
5. Remove it exactly once from the source.
6. Add it exactly once to the destination.
7. Record the change in Undo/Redo history.
8. Avoid partially updating the Store if validation fails.

Show a clear user-facing error if the move cannot be completed.

Do not silently lose the item.

## Mobile and responsive behavior

Test the gear row on:

- Mobile-width layout

On narrow screens:

- It may wrap to another line if needed.

- Long category names such as `Clothing Packed` and `Toiletries + Med` must remain readable.
- Do not make the entire checklist horizontally unusable.

Do not complete the broader toolbar/mobile audit in this task. Only make the Move control fit cleanly into the existing responsive layout.
