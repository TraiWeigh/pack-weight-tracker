8. CATEGORY REORDER — TRUE FINGER-FOLLOW FLOATING DRAG
============================================================

R004 created a raised/floating impression, but review found that the dragged category does not actually stay attached to the finger throughout the full drag distance.

CORRECT THIS.

WHEN DRAGGING WITH THE SIX-DOT REORDER HANDLE:
- the dragged category visibly rises above the stack;
- it remains the actual category being dragged;
- it follows the user's finger DIRECTLY throughout the full vertical drag distance;
- do not artificially clamp the visual movement to a small +/- offset;
- do not allow the floating style to jump to another category when list order changes underneath it;
- track the dragged category by stable identity, not only its original array index.

FLOATING APPEARANCE
- restrained elevation/shadow;
- slight visual separation from the flush stack;
- no excessive scaling;
- no bounce/overshoot;
- preserve wedge, color, text, weight, and row content while floating.

TARGET FEEDBACK
When the floating category reaches/touches a category it can switch/reorder with:
- that valid target dims SLIGHTLY;
- only the current valid target dims;
- the floating category itself does not dim;
- previous target returns to normal immediately when the dragged category moves away;
- new valid target becomes the only dimmed target.

RELEASE
- dragged category settles smoothly into its final position;
- settles FLUSH with the category stack;
- all target dimming disappears;
- no category remains elevated/transformed/dimmed.

GESTURE COEXISTENCE
- six-dot handle remains the reorder initiation control;
- normal category taps do not reorder;
- slide-to-delete must not start reorder;
- reorder must close any open slide-to-delete reveal before beginning;
- vertical category scrolling outside the handle remains normal.

- This aligned six-dot column remains the drag anchor for Part 8.
