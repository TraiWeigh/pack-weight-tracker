============================================================
USER-AUTHORIZED PRODUCT BEHAVIOR TO ANALYZE
============================================================

The USER has approved the following intended behavior:

A. VIEW MODE CHECKBOXES
- View mode should allow the user to check and uncheck checklist item boxes.
- View mode must remain non-structural:
  - no editing item names
  - no editing weights
  - no editing quantities
  - no editing categories
  - no reordering
  - no structural list edits
- Checking/unchecking is checklist progress, not a structural list edit.

B. CROSS-DEVICE SYNC
- Checked/unchecked state should sync between devices for the same signed-in user/list.
- Example:
  - check an item on iPhone
  - open the same list on Mac/tablet
  - that item should appear checked there after sync

C. VISIBLE SYNC STATUS
- Show a visible sync-status indicator so the user knows whether checkbox state is current.
- Desired user-facing states include:
  - `Last synced: Today at 9:28 PM`
  - `Syncing…`
  - `Offline — changes waiting to sync`
- Exact placement is NOT authorized yet; diagnostic should identify the best existing UI location/pattern.
- Prefer a location near the current file-name/toolbar area if that fits the active design without clutter.

D. PRINT VIEW
- Print View should inherit the current synced checked/unchecked state by default.
- Print View must NOT automatically clear checkmarks.
- If the user wants an unchecked/clean print, they must explicitly choose a clear option first.
- Working label concept:
  `Clear Checkmarks for Print`
- The clear-for-print action must be NON-DESTRUCTIVE:
  - it affects only the print representation/session
  - it must NOT uncheck the actual saved/synced TrailWeigh checklist
  - it must NOT overwrite the synced checkbox state
- Closing/exiting Print View should leave the real checklist state unchanged.
