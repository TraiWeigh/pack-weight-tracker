# PART 2 — INVESTIGATE THE ROOT CAUSE FIRST

The v5 checklist schema reportedly already contains:

`pieColors?: Record<string, string>`

Do not create a second competing color-state system.

Determine exactly why selected colors are not reliably restored.

Inspect whether the problem is caused by one or more of these:

1. The color selector updates component-only state instead of the working checklist store.
2. The current working store contains `pieColors`, but Save omits it.
3. Save As omits it.
4. Locker serialization omits it.
5. Locker loading drops it.
6. `parseV5()` drops or replaces it.
7. A default-color initializer overwrites restored colors after loading.
8. A mount effect overwrites restored colors.
9. New-file creation omits it.
10. Cross-tab initialization overwrites it.
11. Category renaming or alias migration disconnects saved colors from category names.
12. The Weight Distribution component receives default colors instead of the restored file colors.

Record the confirmed root cause before implementing the fix.

Do not guess.

# PART 3 — REQUIRED PER-FILE BEHAVIOR

Each Locker file must have its own independent Weight Distribution colors.

## File A and File B independence

Required example:

- File A uses a red color for Backpack.
- File B uses a blue color for Backpack.
- Saving File A must preserve red.
- Saving File B must preserve blue.
- Opening File A must restore red.
- Opening File B must restore blue.
- Changing File A must not alter File B.

Do not store pie colors only as one global preference shared by every file.

## Immediate working-state update

When the user selects a new Weight Distribution color:

- The chart updates immediately.
- The current working checklist store updates immediately.
- The correct category-color entry is updated.
- Other category colors remain unchanged.
- No saved Locker file changes until the user performs Save or Save As.

Do not automatically overwrite a saved file merely because a color was selected.

## Save

When saving an existing active Locker file:

- Include the current complete `pieColors` record.
- Update only the active Locker file.
- Preserve its existing ID and name.
- Do not alter another saved file.
- Preserve all gear items, categories, backgrounds, units, and other saved settings.

## Save As

When using Save As:

- Create a new Locker entry with a new ID.
- Copy the current `pieColors` into the new file.
- Make the new file the active saved file.
- Preserve the original saved file unchanged.

## Open from Locker

When opening a Locker file:

- Restore that file’s exact `pieColors`.
- Do not leave colors from the previously viewed file on screen.
- Do not replace restored colors with defaults after rendering.
- Restore colors whether the file opens in the current tab or a new tab.

## Refresh

After opening a saved file and refreshing the page:

- Restore that same file’s colors.
- Do not revert to default colors.
- Do not use colors from another open tab.

## New

TrailWeigh’s intended New behavior copies the currently visible checklist but unchecks all gear items.

New must also copy the current file’s `pieColors` into the new unsaved working copy.

Requirements:

- The original file remains unchanged.
- The new working copy uses the same colors.
- The new working copy has no active Locker-file identity.
- Its first Save requires a filename.
- Saving it creates a separate Locker file.

## Reset

Reset currently clears gear items from the current working list while preserving the list structure and unrelated visual settings.

Reset must not unexpectedly erase the current file’s pie-color preferences.

Preserve the current `pieColors` unless current verified Reset requirements explicitly state otherwise.

## Older saved files

Older Locker files may not contain `pieColors`.

They must continue opening safely.

For an older file without `pieColors`:

- Use the current default color set.
- Do not throw an error.
- Do not reject the saved file.
- Do not alter its gear data.
- Add `pieColors` naturally the next time the user saves it.

Do not require a manual migration.
