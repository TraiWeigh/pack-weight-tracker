Temporary Real-iPhone Safari Viewport Diagnostic
DIAGNOSTIC ONLY — DO NOT FIX OR REDESIGN THE LAYOUT YET

PURPOSE
We have real iPhone Safari evidence that TrailWeigh is not fitting the visible browser area correctly.

USER-OBSERVED FAILURES
1. Safari's bottom address bar/browser chrome remains visible while scrolling.
2. TrailWeigh has a problem at the bottom of the screen where the app and Safari browser chrome compete for space.
3. TrailWeigh appears too large for the actual visible iPhone Safari area vertically.
4. TrailWeigh also appears too large / clipped relative to the actual visible iPhone Safari width.
5. Chromium/Playwright geometry previously passed at 390×844, but the real iPhone recording did NOT pass. USER device evidence is authoritative.

GOAL OF THIS TASK
Add a TEMPORARY diagnostic tool that lets the user capture the real Safari viewport and TrailWeigh geometry on the actual iPhone.

Do NOT attempt to solve the viewport problem in this task.

TEMPORARY ACTIVATION
Make the diagnostic OFF by default.

Prefer activating it with a URL query parameter so normal TrailWeigh is completely unaffected, for example:

?twViewportDebug=1

Use the project's actual current route safely rather than hardcoding an obsolete route.

When the parameter is absent, the diagnostic must not render and must not affect layout.

DIAGNOSTIC PANEL
When enabled, render a small temporary overlay that:
- is readable on iPhone;
- can be collapsed/expanded;
- stays above normal app content without changing the app's measurements;
- does not consume normal document-flow space;
- does not itself change the measured viewport;
- does not block normal scrolling except while the user is deliberately tapping its controls.

The panel should update live on:
- page load;
- window resize;
- window orientation change;
- visualViewport resize;
- visualViewport scroll, if available.

- window.innerHeight

- visualViewport.pageLeft
- visualViewport.pageTop

On a checklist screen, capture bounding rectangles for:
- first visible category wedge/row

The purpose is to determine whether the apparent horizontal oversizing is:
- the entire shell,
- a fixed layer,
- a wedge/category row,
- clipping from overflow rules,
- browser zoom/scale,
- or a layout-vs-visual viewport mismatch.

- computed width / max-width / min-height for the TrailWeigh root
