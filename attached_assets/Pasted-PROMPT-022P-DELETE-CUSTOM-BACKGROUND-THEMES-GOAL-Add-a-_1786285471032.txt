PROMPT 022P — DELETE CUSTOM BACKGROUND THEMES

GOAL

Add a Delete option for user-created/custom Background Themes.

CURRENT UI

In the custom-theme editor, the theme name appears above the photo slots.

Example:

Test 3          0/10       [pencil icon]

Add a small TRASH CAN icon button immediately to the RIGHT of the existing
pencil/edit icon.

The intended layout is conceptually:

Test 3          0/10       [pencil] [trash]

The trash icon deletes the CUSTOM THEME.

==================================================
0. BACKUP / CHANGE PROTECTION
==================================================

Before changing anything:

1. Create the normal Replit project checkpoint/backup.

2. Inspect the existing custom Background Theme architecture.

3. Determine:
   - How custom themes are stored
   - How their names are stored
   - How custom photos are stored
   - How saved gear lists reference a theme
   - How the currently selected background references a theme
   - How shared snapshots/links preserve backgrounds
   - Whether uploaded photos can be shared by more than one theme

4. Make the smallest reasonable change.

5. Do NOT rewrite the Background Theme system.

6. Preserve:
   - Existing built-in themes
   - Existing custom themes
   - Existing custom photos
   - Fit / Fill
   - Showcase
   - Background selection
   - Undo/redo behavior
   - Saved gear lists
   - Shared links
   - User/account isolation

7. Inspect the COMPLETE final diff.

8. Revert unrelated changes.

9. Run the existing TrailWeigh regression test suite.

==================================================
1. ADD TRASH ICON
==================================================

For USER-CREATED CUSTOM THEMES only:

Add a trash-can icon button immediately to the RIGHT of the existing
pencil/edit icon.

Example:

Theme Test 3                 0/10   ✎   🗑

Use the existing TrailWeigh icon style.

Requirements:

- Simple outline-style trash icon
- Similar visual size to the pencil icon
- Similar stroke weight
- Same vertical alignment
- Similar clickable/tap target
- Appropriate Light/Dark mode color
- Hover state
- Keyboard focus state

Do NOT make the trash icon oversized or visually dominant.

==================================================
2. BUILT-IN THEMES CANNOT BE DELETED
==================================================

The trash/delete-theme button must appear ONLY for custom themes created by
the user.

Do NOT allow deletion of built-in/default TrailWeigh themes.

Examples of system/built-in themes should remain protected according to the
current implementation.

Do not merely hide the icon while leaving an unrestricted delete endpoint.

Protect this at the data/action layer as well where appropriate.

==================================================
3. DELETE CONFIRMATION
==================================================

Clicking the trash icon must NOT immediately delete the theme.

Open a confirmation dialog.

Use wording substantially like:

Delete Custom Theme?

Delete “Test 3” and its custom background photos?

This action cannot be undone.

Buttons:

Cancel

Delete Theme

Use the ACTUAL theme name.

Example:

Delete “Theme Test 3” and its custom background photos?

Do not ask for the user's account password.

This is a simple owner-confirmation action.

==================================================
4. DELETION IS PERMANENT
==================================================

If the user confirms:

Delete the custom theme from that user's Background Themes collection.

Also remove custom photo records/assets that belong exclusively to that
deleted theme where safe and appropriate.

IMPORTANT:

Before deleting physical uploaded image assets, inspect whether any asset is
referenced elsewhere.

Do NOT accidentally delete an image that is still legitimately used by
another custom theme or another protected record.

Avoid leaving unnecessary/orphaned custom-theme files where safe cleanup is
possible.

Document the storage behavior in the report.

==================================================
5. CANCEL
==================================================

If the user selects:

Cancel

Expected:

- Close confirmation
- Theme remains
- Photos remain
- Current background remains
- No data changes occur

==================================================
6. IF THE DELETED THEME IS CURRENTLY SELECTED
==================================================

If the custom theme being deleted is the CURRENTLY ACTIVE background theme:

After successful deletion:

1. Remove the deleted theme.
2. Switch the current working view to the normal safe/default TrailWeigh
   background/theme.

Use the existing default background behavior rather than inventing a new
special theme.

Do NOT leave:

- Blank broken background
- Missing-image icon
- Invalid theme ID
- JavaScript error

==================================================
7. SAVED GEAR LIST PROTECTION
==================================================

Deleting a custom theme must NOT corrupt a saved TrailWeigh gear list.

Inspect how saved lists reference custom backgrounds.

If a saved list references a custom theme that the owner later deletes:

Use a safe fallback according to the existing architecture.

The saved gear data must remain intact:

- Items
- Categories
- Quantities
- Weights
- Checked states
- File name
- File ID

Deleting a BACKGROUND THEME must never delete or corrupt the GEAR LIST.

==================================================
8. SHARED-LINK PROTECTION
==================================================

Inspect how existing Shared TrailWeigh Links preserve backgrounds.

Deleting an owner's custom theme must not cause an existing Shared Link to:

- Crash
- Show a broken-image icon
- Fail to load the gear list
- Expose an invalid internal reference

If shared snapshots contain their own durable background snapshot/reference,
preserve that established behavior.

If the shared page depends directly on a deleted live custom-theme record,
provide the safest existing/default fallback.

Do NOT redesign the sharing architecture in this prompt.

Document the discovered behavior.

==================================================
9. ACCOUNT ISOLATION
==================================================

A user may delete only THEIR OWN custom themes.

Deletion must never affect:

- Another user's themes
- Another user's photos
- Another user's gear lists
- Another user's background library

Preserve account isolation.

==================================================
10. DELETE ICON ACCESSIBILITY
==================================================

The trash icon must be a real accessible button.

Provide an accessible label using the actual theme name.

Example:

Delete Theme Test 3

Requirements:

- Keyboard focusable
- Enter/Space activation as appropriate
- Visible focus state
- Tooltip where consistent with TrailWeigh
- Reasonable touch target on mobile

Do not rely on the trash symbol alone for assistive technology.

==================================================
11. PENCIL / EDIT BUTTON
==================================================

Preserve the existing pencil/edit functionality.

The layout should become:

[pencil] [trash]

Do NOT:

- Replace pencil with trash
- Change rename behavior
- Make clicking the pencil delete anything
- Merge edit and delete into a dropdown unless technically required

Two simple icon buttons are preferred.

==================================================
12. VISUAL SPACING
==================================================

Keep the icons visually grouped.

There should be a small consistent gap between:

Pencil
Trash

Do not create a large empty space between them.

Both should align with the existing:

0/10

photo-count indicator.
