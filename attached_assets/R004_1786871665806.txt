1. CATEGORY + ITEM SLIDE-TO-DELETE
============================================================

Replace the visible resting trash-can delete controls for BOTH:
- category rows/headers;
- individual item rows.

REQUIRED GESTURE DIRECTION
The delete gesture must begin at or near the RIGHT EDGE of the category/item row and move LEFT.

Required behavior:
- the row itself follows the user's finger left;
- the destructive Delete action is revealed underneath on the RIGHT side;
- this right-edge-to-left direction is required;
- vertical scrolling remains natural;
- mostly vertical movement must scroll the list and must NOT reveal Delete;
- slight diagonal movement must not accidentally trigger the delete reveal;
- use deliberate horizontal-vs-vertical gesture disambiguation.

RELEASE / SETTLE
On release, the row settles smoothly into either:
1. closed/resting position; or
2. open/revealed Delete position.

Requirements:
- short/incomplete swipe returns closed;
- intentional swipe opens to the stable Delete-reveal position;
- no bounce;
- no overshoot;
- reversal during the drag should work naturally.

DESTRUCTIVE SAFETY
- Swiping must NEVER immediately delete the category/item.
- Swipe only reveals a clearly labeled Delete action.
- The user must deliberately activate Delete afterward.
- Preserve existing delete confirmation/safeguards.
- Category deletion must retain confirmation because it can remove contained items.
- Item deletion must not weaken any existing safeguards.
- Preserve existing Undo behavior if deletion already participates in Undo.
- Do not invent a new undo architecture.

OPEN-ROW MANAGEMENT
- Only ONE category/item delete reveal may remain open at a time.
- Opening another row closes the previous row.
- Tapping elsewhere closes the open reveal.
- Beginning normal vertical scrolling closes the open reveal.
- Opening/switching a bottom deck must not leave a delete reveal stranded open.
- Reordering a category must close any open delete reveal first.

VISUAL
- Remove the visible resting trash-can icon/button from category rows.
- Remove the visible resting trash-can icon/button from item rows.
- Remove any permanent horizontal space reserved for those trash icons.
- Do not add replacement floating delete buttons.
- The revealed Delete action may use a restrained destructive red treatment.
- Keep the flat/flush V3 design.
- Keep category wedges.

ACCESSIBILITY
Swipe must NOT be the only deletion path.

Provide an accessible non-swipe delete action without restoring a permanently visible trash-can control.

Acceptable approaches within current architecture:
- screen-reader-accessible row action;
- keyboard/focus-accessible Delete action;
- existing contextual action surface if already present.

Do not create a large new menu system only for this.

2. CATEGORY REORDER — RAISED / FLOATING DRAG STATE
============================================================

When dragging a category using the existing SIX-DOT reorder handle:

DRAGGED CATEGORY
- The category being moved must visibly rise above the category stack.
- It should appear to float over the other categories.
- It follows the finger directly while raised.
- Use restrained visual elevation:
  - subtle shadow/depth;
  - slight separation from the flush stack;
  - no dramatic bounce;
  - no excessive scaling.
- Preserve the category's own wedge, color, text, and contents while dragging.
- The floating visual must remain attached to the ACTUAL dragged category even after crossing/reordering positions.
- Do not determine floating styling only from the category's original array index if that can cause the wrong category to receive the lifted style.

VALID TARGET FEEDBACK
When the floating category reaches/touches another category that it can switch/reorder with:
- that target category dims SLIGHTLY;
- only the current valid target dims;
- the dragged/floating category itself does not receive the target dimming;
- as soon as the floating category moves away, the previous target immediately returns to normal;
- when it reaches a different valid target, only that new target dims.

RELEASE
- On release, the dragged category settles smoothly and FLUSH into its new position.
- All dimming disappears immediately.
- The floating elevation disappears after settling.
- No category should remain partially transformed, dimmed, scaled, or elevated.

GESTURE INTEGRATION
- Six-dot handle remains the reorder initiation control.
- Normal category taps/accordion behavior must not start reorder.
- Reorder must coexist cleanly with slide-to-delete.
- Starting reorder closes any open delete reveal.
- A delete swipe must not accidentally trigger reorder.
