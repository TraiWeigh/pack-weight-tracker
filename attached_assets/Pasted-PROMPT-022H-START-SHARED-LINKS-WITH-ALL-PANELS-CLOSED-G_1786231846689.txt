PROMPT 022H — START SHARED LINKS WITH ALL PANELS CLOSED

GOAL

Update the Shared Link / Shared Pack List startup behavior.

Whenever a shared TrailWeigh link is opened or refreshed:

PRESERVE:
- The shared file.
- The shared file's gear and weights.
- The shared file's saved checked/unchecked item state.
- The shared file's background.
- Existing Shared Link permissions and temporary-session behavior.

BUT:

START ALL COLLAPSIBLE PANELS CLOSED.

This should match the clean-start behavior implemented for the private Checklist workspace in Prompt 022G.

==================================================
1. REQUIRED SHARED-LINK STARTUP STATE
==================================================

When a recipient opens a Shared Pack List link:

[ ] All gear-category panels start collapsed.

[ ] Pack Summary starts collapsed.

[ ] Weight Distribution starts collapsed.

[ ] Any other checklist-level collapsible panels that normally begin closed should start collapsed.

[ ] Temporary toolbar menus or popovers are closed.

[ ] Background-selection panels are closed.

[ ] Preview/modal/dialog UI is not unexpectedly open.

Only the visual open/closed state should reset.

Do NOT alter the actual shared gear data.

==================================================
2. PRESERVE SHARED CHECKED / UNCHECKED ITEMS
==================================================

"All panels closed" does NOT mean "all items unchecked."

The shared list must preserve exactly what the owner shared.

Example:

Owner's shared list contains:

- Tent — checked
- Quilt — checked
- Rain jacket — checked
- Camp chair — unchecked

When the recipient opens the link:

- Those saved checked/unchecked states remain exactly as shared.
- The gear categories containing them simply begin collapsed.

Do not reset item selection.

==================================================
3. PRESERVE THE SHARED BACKGROUND
==================================================

The shared list must continue to display the same background associated with the shared file/view.

Preserve the current Shared Link behavior for:

- Built-in backgrounds
- Custom backgrounds, where supported
- Theme/background selection
- Fit / Fill state, where applicable

Do not replace the owner's background with a default background merely because the panels are initialized closed.

Required result:

SAME SHARED FILE
+
SAME BACKGROUND
+
SAME SAVED CHECKED ITEMS
+
ALL PANELS CLOSED

==================================================
4. REFRESH BEHAVIOR
==================================================

The rule must also apply when the recipient refreshes the Shared Link page.

Example:

1. Recipient opens a shared link.
2. All panels begin closed.
3. Recipient opens several categories.
4. Recipient expands Pack Summary.
5. Recipient refreshes the browser.

Expected:

- Same shared list reloads.
- Same shared background remains.
- Saved shared checkbox state remains.
- All category panels return to closed.
- Pack Summary returns to closed.
- Weight Distribution returns to closed.

Do not persist expanded/collapsed UI state across Shared Link reloads.

==================================================
5. CURRENT SESSION BEHAVIOR
==================================================

After the Shared Link loads, the recipient must still be able to use the interface normally.

If the recipient:

- Opens a category
- Opens Pack Summary
- Opens Weight Distribution

those panels should remain open during the current session according to the existing UI behavior.

Do NOT continually force panels closed while the user is interacting with the page.

The automatic reset happens only on:

- Initial Shared Link load
- Browser refresh
- Reopening the Shared Link

==================================================
6. DO NOT MODIFY THE OWNER'S SAVED FILE
==================================================

Resetting panel state is a viewer-side UI behavior only.

It must NOT:

- Save anything back to the owner's file.
- Change the owner's category states.
- Change checked items.
- Change weights.
- Change quantities.
- Change categories.
- Change the background.
- Change the shared file.

The owner should never see changes merely because another person opened or expanded panels in a Shared Link.

==================================================
7. PRESERVE TEMPORARY SHARED-LINK INTERACTION
==================================================

Preserve the current Shared Pack List temporary-session behavior.

Where currently supported, recipients may:

- Browse the list.
- Expand/collapse categories.
- Temporarily check/uncheck items.
- Make allowed temporary session changes.
- Print.
- Preview.
- Save their own copy where supported.

Those temporary viewer interactions must still not alter the owner's saved original.

Do not change permissions.

==================================================
8. SHARED LINK MUST NOT REPLACE PRIVATE LAST-ACTIVE FILE
==================================================

Prompt 022G established that opening a Shared Link must NOT replace the signed-in user's remembered private active file.

Preserve that behavior.

Example:

User's private last-active file:

"PCT Sierra 2026"

User opens someone else's Shared Pack List link.

Later they return to their private TrailWeigh workspace.

Expected:

"PCT Sierra 2026" remains their remembered private active file.

Do not let Prompt 022H change that behavior.

==================================================
9. PRESERVE PROMPT 022F FOOTER FIX
==================================================

Prompt 022F fixed the Shared Link footer overlay and has been user verified.

Do NOT regress it.

The footer must continue to:

- Remain in normal document flow.
- Appear after all shared-page content.
- Never float over the checklist.
- Never cover Pack Summary, Shared Files, Scan Gear List, or other content.
- Work correctly on long and short shared pages.

Do not modify footer positioning unless absolutely necessary.

==================================================
10. INSPECT SHARED-LINK INITIALIZATION FIRST
==================================================

Before coding, inspect the current Shared Pack List implementation.

Determine:

- How category open/closed state is initialized.
- How Pack Summary open/closed state is initialized.
- How Weight Distribution state is initialized.
- Whether any panel state is currently inherited from the owner.
- Whether any panel state is stored in localStorage/sessionStorage.
- Whether Shared Link UI state and private Checklist UI state share hooks/components.

Reuse the clean initialization logic from Prompt 022G where practical.

Do not duplicate large blocks of state-management code unnecessarily.

However, do not couple Shared Link viewer behavior to private saved-file persistence.

==================================================
11. SHARED-LINK PRIVACY / PERMISSIONS
==================================================

Do not add private-owner controls to Shared Links.

Shared viewers must still NOT gain access to:

- Rename
- Delete
- Owner-only Locker controls
- Private file-management controls

Preserve current sharing permissions exactly.
