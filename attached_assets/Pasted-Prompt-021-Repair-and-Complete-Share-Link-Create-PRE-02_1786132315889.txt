Shared viewing must not modify the sender’s originals.

==================================================
5. DELETE PROTECTION
==================================================

A shared-view recipient must NOT be able to delete a shared file without the existing required deletion password/security mechanism.

Do not weaken or bypass the current Locker deletion protection.

Viewing a shared file must never count as ownership permission to delete the sender’s original.

==================================================
6. COPY / ADD TO MY TRAILWEIGH
==================================================

Provide an action that allows the recipient to add/copy a shared saved file into their own TrailWeigh.

Required behavior:

- Copy creates a NEW independent file belonging to the recipient.
- It must have its own new file ID.
- It must NOT remain linked to the sender’s file.
- Recipient edits/saves must never overwrite or modify the sender’s file.
- Sender changes later must never silently overwrite recipient’s copied file.
- Preserve the copied file’s gear/content and supported saved appearance at the moment it is copied.

If the recipient is not signed into/does not have the required TrailWeigh account:
- offer the existing account creation/sign-in path before completing the copy.
- do not discard the intended shared file during that process.

Do not create duplicate copies accidentally from one click.

7. STATE/DATA OWNERSHIP PROTECTION
==================================================

STRICT RULES:

Sender saved file:
- remains sender-owned
- Share viewing cannot modify it
- recipient copy cannot overwrite it

Shared representation:
- view/copy source only
- must not become a writable reference to sender storage

Recipient copy:
- new independent ID
- recipient-owned
- separate persistence

Never:
- rewrite existing Locker files merely because they are shared
- migrate/delete existing user files
- replace existing file IDs
- copy active appearance from unrelated tabs
- use shared temporary state as permanent sender data
- expose deletion privileges by sharing

STOP and explain why before implementing it.
