The “Analyze Again” button in Scan Gear List does not work.

Current workflow:

1. An image is uploaded and read with OCR.
2. TrailWeigh opens “Review Extracted Text.”
3. The user edits the OCR text into clearer item-and-weight lines.
4. Clicking “Analyze Again” produces no visible result.

Fix the actual Analyze Again workflow.

## Relevant files

Inspect:

- `artifacts/pack-checklist/src/components/ImportGearPanel.tsx`
- `artifacts/api-server/src/routes/importGear.ts`
- The existing `POST /api/parse-text` endpoint

Do not create another parsing endpoint or another review component.

## Required button behavior

When the user clicks Analyze Again:

1. Read the current edited text from the textarea.
2. Confirm the text is not blank.
3. Show a temporary button state:
   `Analyzing…`
4. Send the edited text to:
   `POST /api/parse-text`
5. Wait for the response.
6. If one or more gear items are returned:
   - Convert them into the existing editable review-row format.
   - Preserve Type, Description, Weight, Unit, destination, and import-selection fields.
   - Switch from “Review Extracted Text” to the normal editable review table.
7. If no items are returned:
   - Remain on “Review Extracted Text.”
   - Preserve the user’s edited text.
   - Show:
     `No gear items were recognized. Format each item on its own line, such as: Tent — 18.5 oz`
8. If the request fails:
   - Preserve the edited text.
   - Show:
     `The text could not be analyzed. Please try again.`

Do not silently do nothing.

Trace the rendered button click and determine whether:

- The returned items are not being placed into review state

## Request format

Make the frontend and backend use the same JSON structure.

For example:

Frontend request:

`{ "text": editedText }`

Backend response:

`{ "items": [...], "remainder": "..." }`

Use the project’s actual field names, but they must match exactly.

Make sure the API server has JSON body parsing enabled for this endpoint.
