Prompt ID: 017C
Prompt title: Stop Landscape Shaking When an Active Background Is Displayed

Repair the remaining Landscape-thumbnail shaking defect.

This is a focused correction to Prompt 017B.

Do not start Prompt 018 or modify unrelated TrailWeigh features.

# CONFIRMED USER TEST RESULT

Prompt 017B did not fully fix the defect.

The user confirmed this exact behavior:

- When Background is Clear and no image background is active:
  - Landscape thumbnails do not shake.

- When a built-in or custom image background is active:
  - Moving the cursor across the built-in Landscape thumbnails causes visible shaking or jitter.

This means the defect is connected to the active full-screen background, background rendering, or a hover-triggered interaction between the Landscape thumbnails and the background layer.

Do not assume the thumbnail CSS alone is the cause.

# REQUIRED FINAL RESULT

Landscape thumbnails must remain completely stationary when:

- Background is Clear
- A built-in Landscape background is active
- A custom-theme photo is active
- Fill Screen is selected
- Fit Image is selected
- Light is selected
- Dark is selected
- Fade/darken is adjusted
- The selected thumbnail displays its border and checkmark

Moving the cursor slowly or rapidly over the Landscape thumbnails must not:

- Move the thumbnails
- Resize the thumbnails
- Shift neighboring thumbnails
- Recreate or reload the active background
- Change the active background
- Cause background flashing
- Cause the Background Edit panel to move
- Cause a scrollbar to appear or disappear
- Write background data to storage
- Trigger unnecessary React state changes

# PART 6 — STABILIZE THE ACTIVE BACKGROUND LAYER

- Do not change its React `key` during hover.

- Do not toggle background classes unnecessarily.
- Do not change background positioning during hover.
- Do not change Fill/Fit during hover.
- Do not change fade or filter during hover.

# PART 7 — OBJECT URL AND IMAGE REFERENCE SAFETY

For custom photos stored in IndexedDB:

- Resolve the active photo object URL only when the selected photo changes.
- Memoize or retain the current usable URL appropriately.
- Do not regenerate the URL because a Landscape thumbnail hovered.
- Revoke an old URL only when it is no longer needed.
- Do not revoke the active URL during unrelated renders.
- Do not create multiple URLs for the same active photo during cursor movement.

For built-in Landscape backgrounds:

- Keep the same image URL while hover state changes.
- Do not append changing cache-busting values.
- Do not preload and replace the selected URL repeatedly.

Document whether object-URL recreation contributed to the shaking.
