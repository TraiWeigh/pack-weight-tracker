PRIMARY PROBLEM

Many Word packing lists are organized like this:

Heading: Backpack
table:
Type | Name | Weight | Unit | Qty
Backpack | Durston Kakwa 55 | 30.1 | oz | 1

Heading: Shelter
table:
Type | Name | Weight | Unit | Qty
Tent | Zpacks Duplex | 18.5 | oz | 1

The table itself does NOT repeat the Category column.

TrailWeigh must understand that the Word heading above the table supplies the category context for the rows in that table.

PRIMARY GOAL

For DOCX import only:

When a standard Microsoft Word heading paragraph appears before an item table, treat that heading as the source Category context for the following table rows until another relevant heading replaces it.

At minimum support:
- Heading 1
- Heading 2

Do not require the table itself to contain a Category column when a valid category heading is available immediately before it.

CATEGORY HEADING PRECEDENCE

Use this order of trust:

1. Explicit per-row Category column in the table, if present and meaningful.
2. Existing high-confidence semantic item-routing rules that intentionally override source grouping, such as:
   - worn routing;
   - medical/repair routing;
   - Fuel consumable routing;
   - canonical Backpack normalization.
3. DOCX heading category context.
4. Existing safe fallback behavior.

This prevents a heading from undoing the routing fixes already verified.

Example:
Heading = Kitchen
Type = Fuel Canister
If the existing verified semantic rule says Fuel belongs in Consumables/Expendables:
keep Fuel there.
