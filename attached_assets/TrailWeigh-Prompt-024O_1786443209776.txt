PHASE 3 — HEADER-ROW DETECTION
Do not assume the first physical row is always the table header.

For CSV and spreadsheet/tabular input, inspect a small bounded range at the beginning of the file (for example the first 10–20 meaningful rows) and select the strongest likely header row based on recognized field names.

Required behavior:
- Test 06 must recognize the second row as the real header row even though a title row is above it.
- Do NOT hard-code "row 2".
- A normal file whose header is already row 1 must continue to work.
- Blank rows before a header must not break detection.
- A title row must not become a gear item.
- A trailing TOTAL row must not become a gear item.
- Do not scan arbitrarily deep into huge files; keep header detection bounded and cheap.

Prefer a simple scoring/recognition method rather than brittle file-specific rules. A likely header should contain an item-identity field plus one or more additional recognized fields such as Category, Weight, Unit, or Quantity.

PHASE 4 — NORMALIZE COMMON COLUMN-HEADER ALIASES
Match headers case-insensitively and tolerate ordinary spaces/punctuation differences.

Map these source headers to TrailWeigh fields:

A. TRAILWEIGH TYPE / ITEM IDENTITY
Recognize at minimum:
- Type
- Item
- Item Name
- Name
- Gear
- Gear Item
- Equipment
- Product

These values belong in TrailWeigh TYPE, not merely Description.

IMPORTANT PRECEDENCE:
- If the source has an explicit Type column, preserve it as Type.
- If the source has a separate Description/Notes/Details column, preserve that separate text as Description.
- Do not erase or replace a valid Type merely because a Description exists.
- Do not put the item name only into Description when a recognized item-identity column exists.

If TrailWeigh import validation requires a nonblank Description and a row has a valid Type/item identity but no distinct description text, preserve Type and use the Type text as a Description fallback only when necessary. Do not overwrite a valid source Description.

B. DESCRIPTION
Recognize at minimum:
- Description
- Notes
- Details

C. CATEGORY
Recognize at minimum:
- Category
- Group
- Section
- System

D. SUBCATEGORY
Recognize:
- Subcategory
- Sub Category

TrailWeigh currently has one main category level. Do not build nested-category UI in this prompt.
Use a valid main Category when supplied. A Subcategory may be used as a fallback/clue when the main Category is blank, but must not cause items to disappear or overwrite a valid main Category.

E. QUANTITY
Recognize at minimum:
- Quantity
- Qty
- Count
- #

Preserve a valid positive numeric quantity.
Default to 1 only when Quantity is absent, blank, or invalid.
Do NOT silently replace a valid 2, 3, 4, etc. with 1.

F. WEIGHT
Recognize at minimum:
- Weight
- Wt
- Mass

G. WEIGHT UNIT
Recognize at minimum:
- Unit
- Units
- Weight Unit
- WeightUnit

Preserve the current working unit conversion behavior.
Do not regress g, kg, oz, or lb handling.
