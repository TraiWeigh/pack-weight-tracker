# PART 6 — STANDARDIZE THE API RESPONSE

The frontend and server must agree on one response format.

## Successful PDF import

Return a JSON response containing the existing fields needed by Scan Gear List, such as:

- Success state
- Parsed items
- Warnings, if any
- File metadata needed by the current UI

Do not invent a competing import schema if the Word and spreadsheet paths already use a shared schema.

## Known user-facing failures

Return JSON for:

- No file supplied
- Unsupported file type
- File too large
- Empty PDF
- PDF containing no extractable text
- Password-protected PDF
- Corrupt or malformed PDF
- Parsing timeout
- Parser error
- Server capacity or memory issue

Use an appropriate HTTP status while still returning valid JSON.

Example concept:

- `success: false`
- Stable error code
- Clear user-facing message

## Unexpected server error

Catch the exception at the API boundary.

Log the technical error on the server.

Return a safe JSON response.

Do not send:

- An HTML error page
- A stack trace
- An empty response
- A framework-generated error page

The frontend must never need to parse an HTML 502 page as JSON.
