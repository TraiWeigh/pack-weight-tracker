============================================================
USER-VERIFIED FAILURE 1
NATIVE THUMB/FINGER SCROLL MOVES THE CATEGORY STACK
============================================================

USER LIVE OBSERVATION:

When a category is fully expanded into long-category mode and its items fit in the bounded scrolling area between:

- the fixed/open category header above, and
- the fixed Add Item bar below,

the item rows can currently be moved using the ▲/▼ item-scroll chevrons.

BUT:

When the user places a thumb/finger on the item rows and performs a normal vertical drag/swipe, the item rows do NOT behave as the only native scroll surface.

Instead, the OUTER category stack moves vertically.

This is WRONG.

The chevrons must remain an alternate scrolling control.
They must NOT be the only practical way to scroll the item rows.

============================================================
REQUIRED LONG-CATEGORY TOUCH BEHAVIOR
============================================================

While long-category mode is active:

A. List Summary stays fixed.
B. The active category header stays fixed directly below List Summary.
C. The item viewport is the native vertical touch-scroll surface.
D. Add Item stays fixed below the item viewport.
E. Bottom controls stay fixed.
F. A thumb/finger drag over the item area scrolls ONLY the item rows.
G. The outer category stack must not vertically move during that gesture.
H. ▲ and ▼ item-scroll controls must continue to work.
I. Normal item taps must continue to open/close item accordions.
J. Horizontal/other gestures unrelated to this defect must not be changed.

The user must be able to naturally drag the item rows upward and downward with a thumb, just like a normal mobile scroll list.
