PROMPT 022C — REORGANIZE AND SIMPLIFY HELP & HOW-TO

GOAL

Reorganize the existing TrailWeigh Help & How-To page so the instructions follow the order in which a user would normally use TrailWeigh.

This is primarily a HELP CONTENT AND HELP-PAGE ORGANIZATION change.

Do NOT redesign or alter the underlying TrailWeigh checklist functionality merely to match the Help text.

Before changing anything, inspect the current TrailWeigh interface and the existing Help & How-To content so all instructions accurately describe the controls and features that currently exist.

==================================================
1. REQUIRED HELP & HOW-TO ORDER
==================================================

Organize the Help & How-To page into these six main topics, in this exact order:

1. Building Your Gear List
2. Understanding Your Pack Weight
3. Editing Your Gear List
4. Save / Locker
5. Preview / Print / Share
6. Backgrounds & Display

The organization should follow the user's normal workflow:

BUILD → UNDERSTAND → EDIT → SAVE → PREVIEW/PRINT/SHARE → CUSTOMIZE

==================================================
2. CLICKABLE COLLAPSIBLE SECTIONS
==================================================

Use collapsible panels / accordion sections.

IMPORTANT TERMINOLOGY:
These are accordion/collapsible sections, NOT dropdown/select menus.

For all Help topics:

- Make the ENTIRE title row clickable.
- Do not require the user to click only the small disclosure chevron.
- Show a disclosure chevron/caret indicating collapsed versus expanded state.
- All major Help sections should be collapsed by default.
- Clicking the title again should collapse the section.
- More than one section may remain expanded at the same time.
- Provide a visible hover/focus state.
- Keyboard users must be able to expand/collapse sections using Enter or Space.
- Preserve normal accessibility semantics and ARIA state.

Do not add an "Expand All" control.

==================================================
3. BUILDING YOUR GEAR LIST
==================================================

This should be the first major Help section.

Inside it, organize the instructions under:

A. Create / Upload
B. Add / Organize

------------------------------------------
A. CREATE / UPLOAD
------------------------------------------

Explain the different ways a user can begin building a TrailWeigh gear list.

Include:

- Creating a new gear list directly in TrailWeigh.
- Uploading/importing an existing supported gear list using Scan Gear List.
- Reviewing the items TrailWeigh detects before importing them.
- Selecting only the detected items the user actually wants to import.
- Importing those selected items into the TrailWeigh checklist.

MOVE the existing "Scan Gear List" Help information into this section.

REMOVE the separate Help section currently shown as:

"Importing / Scan Gear List"
    "Scan Gear List"

Scanning/importing is not a separate Help category. It is simply another way to BUILD a gear list.

Do not duplicate the Scan Gear List instructions elsewhere.

Use the actual supported upload formats and current Scan Gear List behavior found in the existing TrailWeigh interface/code. Do not invent supported file types.

------------------------------------------
B. ADD / ORGANIZE
------------------------------------------

Explain how to:

- Add gear manually.
- Enter the information TrailWeigh currently accepts for each item.
- Enter quantity and weight.
- Put gear into appropriate categories.
- Move an item from one category to another using the current Move control, if it is present in the live interface.
- Check/select the items the user intends to carry for the current trip.
- Leave other items unchecked when they are not being carried.

MOVE the existing Help information titled:

"Select the gear you are using"

into Add / Organize.

REMOVE "Select the gear you are using" as a separate major Help topic.

Explain that a user can keep gear available in a list while selecting only the gear being used for a particular trip, as supported by the current application behavior.

------------------------------------------
TRIP-, TRAIL-, AND SEASON-SPECIFIC LISTS
------------------------------------------

Include a subsection within Building Your Gear List explaining that one gear setup does not necessarily fit every hike.

Explain that users can create and save lists for:

- Different trails
- Different sections of a trail
- Different trips
- Different seasons
- Different expected conditions

Use examples such as:

PCT — Desert
PCT — Sierra
AT — Summer
AT — Cold Weather
CDT — Colorado
Weekend — Summer
Weekend — Winter

Explain in plain language that a PCT gear list may differ from an AT or CDT gear list, and warmer-season gear may differ from gear needed for colder spring, fall, winter, high-elevation, wet, or other conditions.

Examples of gear needs that may change can include, where appropriate:

- Clothing
- Insulation
- Shelter
- Rain protection
- Water capacity
- Traction
- Other condition-specific equipment

Do not tell users what they personally must carry.

The point is to explain that TrailWeigh allows users to maintain different gear/checklist configurations for different trips.

If the current Save As function is the appropriate way to make another version of a list without replacing the original, explain that here and cross-reference the detailed Save / Save As instructions in the Save / Locker section.

==================================================

Make this the fourth major Help section.

Organize it around:

A. Save / Save As
B. Locker

------------------------------------------
A. SAVE / SAVE AS
------------------------------------------

Explain:

- How to save the current gear list.
- Naming the list.
- What Save does.
- What Save As does.
- The difference between Save and Save As.

Where applicable to the current app, explain that Save As can be useful for making another version of an existing gear list for a different trip, trail, section, or season without replacing the original.

Document the current successful-save confirmation behavior accurately.

------------------------------------------
B. LOCKER
------------------------------------------

Explain the current Locker functions, including only those actually available:

- Opening/loading saved lists
- Keeping multiple named gear lists
- Renaming
- Deleting

Explain that the Locker is associated with the signed-in user's saved lists/private account storage where applicable.

Do NOT say a password is required to delete a Locker file.

Current intended deletion behavior is a simple permanent-deletion confirmation for the signed-in owner.

Do not expose Rename or Delete controls in documentation for a shared-link viewer if those controls are not available to shared viewers.

------------------------------------------

------------------------------------------

------------------------------------------
B. PRINT
------------------------------------------

Explain the practical value of the TrailWeigh gear list as a PACKING CHECKLIST.

Include that users can:

- Print their completed gear list.
- Use the printed copy as a physical packing checklist.
- Check equipment while gathering and packing it.
- Use it for a final equipment check before leaving home or reaching the trailhead.

Explain the current way Print is accessed.

If Print currently exists inside Preview, document it that way.

Do not tell users to use a standalone Print button if one no longer exists.

------------------------------------------
C. SHARE
------------------------------------------

Keep ALL sharing instructions together under Share.

Explain the current Share function and current share-link behavior.

Include that users can share:

- The applicable TrailWeigh gear-list experience/view.
- JUST THE CHECKABLE PACKING LIST when the recipient only needs a simple checklist, if this option currently exists.

Explain the checkable packing list in plain language:

- The recipient can check items off while gathering/packing gear.
- Their checking or temporary session interaction must not modify the owner's saved original.
- Shared lists/checklists can be viewed and printed where currently supported.

This can be useful for:

- Sharing with a hiking partner
- Helping another person prepare for a trip
- Giving someone a packing checklist to work from

DO NOT create a separate Help topic titled:

"Share a Checkable Packing List"

That information belongs inside Share.

IMPORTANT:
Inventory the actual current Share UI before writing the instructions.

Do not claim that a sharing choice exists unless the current interface actually provides it.

If the intended checkable-list sharing functionality exists but the Help text is simply missing it, document it.

Do not implement a new sharing system as part of this Help-content prompt.

==================================================
10. WRITING STYLE
==================================================

The Help & How-To content is for ordinary TrailWeigh users, not programmers.

Use:

- Clear everyday language
- Detailed written instructions
- Short paragraphs
- Step-by-step directions where useful
- The exact names shown on TrailWeigh controls
- Bold control names where that improves readability

Do NOT:

- Add programming terminology
- Add developer implementation details
- Add videos
- Add animations
- Use unexplained technical jargon
- Document removed/nonexistent controls

Assume users are capable of reading and following clear instructions.

Use progressive disclosure through the accordion sections so the page remains visually clean.
