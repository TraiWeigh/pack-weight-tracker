CURRENT OFFICIAL WEB/REPLIT GUIDANCE TO APPLY
==================================================

Use current platform behavior, not guessed string construction.

- Replit development URLs are real `*.replit.dev` URLs intended for Preview/testing.
- After publishing, TrailWeigh will have a normal public deployment origin.
- A shared browser URL should therefore be constructed from the CURRENT app origin
  plus the public review route/token rather than embedding the review payload.
- Clipboard `writeText()` should receive the final URL string only.
- If using the Web Share API, pass the final URL in the `url` field.
- Do not put serialized file/locker JSON into the copied URL or into share `text`.

Preferred conceptual form:

CURRENT APP ORIGIN + `/s/<public-token>`

`https://<current-trailweigh-origin>/s/abc123xyz0`

Do NOT hard-code a specific Replit development domain.

PRIMARY GOAL
==================================================

The owner-facing TrailWeigh Share control must produce a concise,
absolute, valid Public Review URL.

When the user copies/shares it and pastes it into a normal browser address bar:

- the browser recognizes it as a URL;
- it navigates directly to TrailWeigh;
- it opens `/s/<public-token>`;
- Review mode loads;
- no login is required.

The copied/shared content must NOT be:
- serialized gear/locker JSON;
- a data URL;
- a giant encoded payload;
- a search query;
- a relative path with no usable origin;
- malformed due to missing `https://`;
- a comma-separated list of Replit domains;
- an editor/internal URL that reviewers cannot open.
