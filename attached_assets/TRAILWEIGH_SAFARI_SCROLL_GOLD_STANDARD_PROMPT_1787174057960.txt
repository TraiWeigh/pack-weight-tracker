TRAILWEIGH — GOLD STANDARD REPLIT PROMPT
Mobile Safari / iPhone Scroll Architecture Repair

IMPORTANT: Work from the CURRENT Replit state. Inspect first. Do not assume a prior attempted fix landed.

GOAL
Repair the iPhone Safari/mobile vertical-scroll architecture without changing any previously USER-PASS TrailWeigh behavior.

NON-NEGOTIABLE USER-PASS BASELINE
1. The TrailWeigh header is already correct. It must remain permanently fixed and visually/functionally unchanged.
2. Bottom Box Groups are already correct. They must remain permanently fixed and visually/functionally unchanged.
3. On checklist/list screens, the List Summary panel must remain permanently fixed directly beneath the TrailWeigh header.
4. On Home, the green Home hero must remain permanently fixed directly beneath the TrailWeigh header.
5. Only the category/list content on checklist screens and the Home content below the green hero should vertically scroll.
6. Long/open categories must not freeze iPhone Safari or globally disable normal document scrolling.
7. Preserve all existing category/item accordion behavior, paging controls, Add Item behavior, drawers, slide gestures, swipe-to-delete, reordering, checklist semantics, selection state, bottom navigation behavior, and every other prior USER-PASS interaction.

CURRENT KNOWN REGRESSIONS TO VERIFY BEFORE EDITING
Previous read-only audits found:
- The TrailWeigh header is fixed and correct.
- Bottom Box Groups are fixed and correct.
- List Summary is still implemented as sticky rather than a true fixed second layer.
- Home is still using an absolute/inner-scroll architecture rather than a true fixed green hero second layer.
- Long-category mode still applies a global body/document lock, including body position fixed / overflow hidden behavior, which conflicts with the newer Safari root/document-scroll architecture.
- The bounded long-category item viewport, category paging controls, and Add Item bar already exist and should be preserved.

B. APPLY THE SMALLEST SAFE REPAIR
Use the smallest reversible implementation that produces this architecture:

CHECKLIST / LIST SCREEN
- TrailWeigh header: fixed at top; unchanged.
- List Summary: true fixed second layer immediately beneath the header.
- Categories/list content: the only normal vertical scrolling content beneath List Summary.
- Bottom Box Groups: fixed at bottom; unchanged.
- Reserve the physical height occupied by the fixed List Summary so category content starts below it and never hides underneath it.
- Preserve any existing List Summary measurement logic that is useful; do not create brittle hard-coded spacing if the panel can vary in height.
- Do not reintroduce the old full-page inner-scroll architecture if the current Safari root/document-scroll architecture is otherwise correct.

HOME
- TrailWeigh header: fixed at top; unchanged.
- Green Home hero: true fixed second layer immediately beneath the header.
- Home content/cards/actions below the hero: vertically scroll independently beneath the fixed hero.
- Bottom Box Groups: fixed at bottom; unchanged.
- Reserve the hero’s actual occupied height so Home content never renders underneath the fixed hero.
- Do not change Home design/content beyond what is required for the scroll architecture.

LONG CATEGORIES
- Remove the GLOBAL document/body lock that makes the entire page fixed or overflow hidden when a long category is open.
- Preserve the existing bounded item viewport for long-category item rows.
- Preserve its max-height/available-height behavior.
- Preserve its internal vertical scrolling.
- Preserve overscroll containment if it is still appropriate.
- Preserve the existing up/down paging controls.
- Preserve the Add Item bar outside the bounded item-row viewport.
- Opening a long category must not freeze root/document scrolling or break iPhone Safari address-bar behavior.
