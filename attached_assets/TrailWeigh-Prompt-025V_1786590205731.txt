IMPORTANT INDEPENDENT REVIEW NOTES FROM CHATGPT
============================================================

ChatGPT reviewed 025U after comparing it with current official Replit,
WebKit/Apple, and Clerk documentation.

025V MUST specifically test these concerns:

A. 025U calls the unauthenticated frozen-snapshot POST a HIGH security issue.
Need to distinguish:
- endpoint intentionally public vs accidentally public;
- abuse/storage risk vs authorization bypass;
- whether current UI can reach/create it;
- whether old legacy clients require it.

B. 025U says there is "no CSRF protection" on the unauthenticated frozen POST.
That may be a CATEGORY ERROR:
- CSRF requires a meaningful victim-authenticated state or ambient credentials.
- If the route is deliberately anonymous and does not act as a logged-in victim,
  the risk may be unauthenticated abuse, not CSRF.
Reclassify precisely.

C. 025U says there is "no payload size limit" on frozen POST.
That cannot be concluded only from the endpoint body.
Inspect:
- Express JSON/body middleware
- route-level middleware
- reverse proxy/platform limits if documented
- any request parser defaults
Do not label "no size limit" VERIFIED until the whole request path is checked.

D. 025U says token collision would cause an "unhandled crash."
Inspect the Express async error path.
Distinguish:
- one request returns 500
- route handler rejection
- process/server crash
Do not use "crash" without proof.

E. 025U says iOS Safari private IndexedDB "may be unavailable."
That may be outdated.
Use current Apple/WebKit primary documentation where available.
Do not rely on generic industry memory.

F. 025U states a ~5MB localStorage limit as if universal.
Storage quota varies by browser/platform.
Reword to a browser-dependent quota unless THIS browser/platform is measured.

G. 025U's Safari 7-day storage statement needs current WebKit nuance.
Current WebKit documentation describes a 7-day cap on script-writeable storage
under its tracking-prevention rules after no user interaction.
Do not reduce this to an unconditional statement that every TrailWeigh first-party
localStorage entry is always deleted after seven calendar days.

H. 025U says development `.replit.dev` Share URLs "break" on production.
The precise rule should distinguish:
- existing URL does not automatically become a production URL;
- development Preview URLs are not an appropriate permanent production link;
- whether an existing development URL remains temporarily reachable is a separate fact.

I. Current official Clerk docs explicitly support `user.deleted` events so an app can
delete or tombstone its own DB records. Reconfirm TrailWeigh's current webhook does
NOT handle that event, but distinguish:
- Clerk account deletion
from
- TrailWeigh application-data deletion.
