PROMPT 023J — HISTORICAL WORKFLOW COST & TIME REPORT

PURPOSE

Create a historical TrailWeigh workflow report that records the actual Replit Agent time, cost, work/action counts, items/lines read, checkpoint information, and prompt outcomes for as many past TrailWeigh prompts as Replit can verify.

This is a REPORTING-ONLY prompt.

DO NOT modify TrailWeigh application code.
DO NOT change UI, backend, database, authentication, storage, themes, files, or user data.
DO NOT fix bugs or add features.
DO NOT estimate or invent historical usage values.

The goal is to build a trustworthy dataset that can later be compared with each prompt's ZIP/report so future Replit time and cost can be estimated more accurately.

--------------------------------------------------
0. BACKUP / CHANGE PROTECTION
--------------------------------------------------

Before doing anything:

1. Create a checkpoint.
2. Inspect the current project and existing workflow-report structure.
3. Do not make any application/source-code changes.
4. The only allowed changes are new/updated reporting files inside workflow-reports/ and the required append to TRAILWEIGH_COMPLETE_WORKFLOW.md.
5. At the end, inspect the complete final diff.
6. If any TrailWeigh application/source file changed, revert that unrelated change before completion.
7. Document the checkpoint and final-diff review in the Prompt 023J report.

Build the most complete prompt inventory possible from:

- TRAILWEIGH_COMPLETE_WORKFLOW.md

- any Replit project/session metadata that is actually accessible

--------------------------------------------------
2. RETRIEVE ACTUAL WORKFLOW METRICS
--------------------------------------------------

For each past prompt, retrieve ONLY values that Replit can directly verify.

Look for these fields when available:

- Prompt number
- Prompt title / short description
- Date/time
- Time worked / "Worked for X minutes"
- Work done / action count
- Items read
- Lines read
- Agent usage / cost in USD
- Whether a checkpoint was created
- Checkpoint identifier or description, if safely available
- Number of files changed, if verifiable
- Report result/status
- User/runtime result when documented
- Whether follow-up/rework was required, when documented

IMPORTANT:

Do NOT calculate a historical cost from time.
Do NOT infer time from timestamps.
Do NOT infer actions or lines read from file sizes.
Do NOT reconstruct missing usage values from guesses.
Do NOT label an estimate as actual.

If Replit cannot retrieve a metric directly, write exactly:

NOT AVAILABLE

For every actual time/cost/action/line metric, identify its source, for example:

- Replit Agent workflow summary
- checkpoint metadata
- billing/usage metadata
- existing Prompt report
- other verifiable Replit metadata

If the value exists only in the Replit UI but Agent cannot access it programmatically, record:

NOT AVAILABLE — UI VALUE NOT ACCESSIBLE TO AGENT

--------------------------------------------------

The report must begin with a clear statement:

"This report contains verified Replit values only. Missing historical time/cost/workflow metrics are marked NOT AVAILABLE and are not estimated."

Include a table with at least these columns:

| Prompt | Title / Scope | Date | Time Worked | Actions | Items Read | Lines Read | Agent Cost | Checkpoint | Result | Rework Needed | Metric Source |

Use actual values only.

For Result, use only:

PASS
FAIL
PARTIAL
NOT TESTED
NOT AVAILABLE

If a previous Replit report claimed PASS but later documented user testing showed a regression or failure, preserve that distinction in Notes rather than silently rewriting history.

Example:

Replit report: PASS
User verification: FAIL
Overall documented outcome: FAIL

Where enough evidence exists, include both the Replit-reported result and the later user-verified result.

## Verified Cost & Time Calibration Data

Report:

- Number of prompts inventoried

- Number with verified actual Agent cost
- Number with verified actions
- Number with verified lines read

- Total VERIFIED Agent cost only where actual cost values exist

- Average verified time per prompt

Also identify broad work categories where the existing reports make classification possible, such as:

- content/documentation
- state/storage

Do not invent category-specific cost averages unless there are verified cost/time values for the prompts in that category.
