==================================================
1. ROOT PROBLEM
==================================================

022W treated portrait responsiveness as:

"put each group on another centered row."

That prevented overlap but changed the intended spatial relationship among the
controls.

The goal is NOT:

Background Edit / Share
File Name
Open / Close + Imperial / Metric
Hide / Preview

all centered as one vertical stack.

The goal is:

KEEP THE ORIGINAL TOOLBAR ZONES AND ALIGNMENTS,
then responsively adapt only when the viewport truly requires it.

==================================================
2. RESTORE THE ESTABLISHED MAIN TOOLBAR GEOMETRY
==================================================

The established TrailWeigh relationship must be preserved:

LEFT ZONE:
Open / Close

CENTER ZONE:
Current saved file-name pill

RIGHT ZONE:
Imperial / Metric

These three zones belong to the same toolbar relationship.

On widths where all three fit:

[ Open | Close ]      [ Current File Name ]      [ Imperial | Metric ]

Requirements:

- Open/Close left edge aligns with the main/category panel left edge.
- Imperial/Metric right edge aligns with the main/category panel right edge.
- File-name pill is visually centered between them.
- File-name pill must not overlap either segmented control.
- Open/Close remains one segmented unit.
- Imperial/Metric remains one segmented unit.

Do NOT center Open/Close and Imperial/Metric together as one combined block.

==================================================
3. PORTRAIT FALLBACK WHEN THREE ZONES CANNOT FIT
==================================================

At narrow phone portrait widths, the three-zone row may not physically fit.

If so, use a deterministic responsive fallback that PRESERVES THE ZONES.

Preferred fallback:

ROW A:
[ Open | Close ]                      [ Imperial | Metric ]

- Open/Close anchored LEFT.
- Imperial/Metric anchored RIGHT.
- Both aligned to the same content-panel gutters.

ROW B:
              [ Current File Name ]

- File-name pill centered.
- This row should be directly associated with the same toolbar area.
- Keep vertical spacing compact.

Do NOT turn Row A into a centered pair.
Do NOT put File Name between unrelated controls.
Do NOT create excessive vertical spacing.

At slightly wider portrait widths, if all three zones fit safely, use the
single-row version again.

==================================================
4. BACKGROUND EDIT / SHARE MUST KEEP THEIR OWN TOOLBAR LOCATION
==================================================

Background Edit and Share are a separate control relationship.

Do NOT treat them as the beginning of one giant centered stack with every
other pill.

Recover their established position from the pre-022V/022W implementation.

On portrait:
- keep them in their own toolbar area
- preserve their established left/right relationship as closely as practical
- use the same outer content gutters
- keep them visually separate from the Open/File/Units toolbar relationship

Do not arbitrarily move them upward or downward solely to make a centered stack.
