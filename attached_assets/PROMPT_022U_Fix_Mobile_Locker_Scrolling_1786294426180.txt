==================================================
2. FIRST DETERMINE WHICH SCROLL CONTAINER IS BROKEN
==================================================

Do not guess.

At mobile width, identify exactly which element is supposed to scroll:

A. the main page/body
B. the Locker file list
C. a nested container
D. another wrapper

Then determine why vertical touch scrolling stops.

Check for:
- body/root overflow:hidden
- fixed-height page wrapper
- Locker max-height with hidden overflow
- nested overflow:auto that does not respond correctly on iOS
- touch-action restrictions
- an invisible overlay intercepting touch events
- modal/body scroll lock not being removed
- footer positioned over the list
- fixed viewport-height calculations
- a parent clipping the Locker contents

Document the actual root cause.

==================================================
3. MOBILE PREFERENCE — AVOID UNNECESSARY NESTED SCROLLING
==================================================

For the Locker on a phone, prefer normal page/document scrolling unless there
is a strong existing design reason for a separate internal Locker scrollbar.

The user should normally be able to swipe vertically on the Locker area and
have the page continue moving naturally.

If Locker currently uses a fixed/max-height internal scrolling area:

Inspect whether that is actually needed.

If not needed on mobile:
- allow the Locker content to expand to fit its saved entries
- let the MAIN PAGE scroll

This is preferred over creating a tiny internal scroll box that is difficult
to discover or operate on iPhone.

Desktop behavior may retain an intentional internal list limit if it is useful,
but mobile must remain obvious and usable.
