AUTHORITATIVE PRODUCT MODEL
============================================================

A. NORMAL WORKING LIST

The normal TrailWeigh website is the category items.

Owner may normally:
- edit item name/type
- edit weight/quantity
- add/delete/move/reorder items
- add/rename/delete/reorder categories
- use current working-list controls
- check/uncheck boxes as already supported

There is NO Edit/Done toggle.

B. PREVIEW IS RENAMED

User-facing label:
`Preview` → `Checklist`

Internal component names may remain unchanged if renaming them adds risk.

C. WORKING-LIST CHECKBOXES = CHECKLIST SELECTION

The normal editable category-item checkboxes determine WHICH ITEMS belong in Checklist.

Required:
- checked/selected category item -> INCLUDED in Checklist
- unchecked category item -> EXCLUDED from Checklist
- Checklist must NOT show every item in the category items

These source-selection checkboxes are separate from the checkboxes used inside Checklist.

D. CHECKLIST

Checklist is the dedicated checkable-list experience.

When Checklist opens:
- show ONLY items currently checked/selected in the working-list categories
- excluded/unchecked category items must not appear
- each included Checklist item displays a checklist-use checkbox
- checklist-use boxes start EMPTY for a fresh Checklist session/state
- checking/unchecking inside Checklist must NOT change category-item selection
- no structural editing controls appear in Checklist

Checklist actions:
- Check
- Uncheck
- Clear
- Print
- Share

E. CLEAR

`Clear`:
- clears/unchecks the checklist-use boxes
- does NOT unselect category items in the category items
- does NOT remove items from Checklist selection
- does NOT delete or restructure anything
- is NOT print-only
- is NOT Edit/Done

F. PRINT

Print operates on the FILTERED Checklist only:
- include only items selected/checked in the category items
- preserve the current Checklist-use checked/unchecked state
- do not add excluded category items
- do not auto-clear

If the user wants an unchecked print:
- use Clear first

G. SHARE

Share operates on the FILTERED Checklist only.
Reuse the existing Share implementation and preserve current isolation.
Do not create a new sharing architecture.
