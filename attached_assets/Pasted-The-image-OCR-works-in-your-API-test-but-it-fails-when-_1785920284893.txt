If the backend receives an empty or truncated buffer, fix the multipart upload or middleware configuration.

## Check how Python receives the image

Confirm that importGear.ts passes the actual uploaded image to image_ocr.py.

If using a temporary file:

- Write the complete uploaded buffer
- Use an absolute file path
- Wait for the write to finish before starting Python
- Confirm the file exists and has a nonzero size
- Delete it only after Python finishes

If passing image data through stdin:

- Use binary-safe input
- Do not convert the image buffer to UTF-8 text
- Do not truncate the buffer

Do not pass a browser object URL, filename alone, or inaccessible frontend path to Python.

## Error handling

Use distinct errors:

- Upload or damaged-file failure:
  “We could not open this image.”

- OCR process failure:
  “We could not read this image. Please try another screenshot.”

- OCR succeeds but finds no useful text:
  “No readable gear-list text was found. Try a clearer image or crop the screenshot closer to the list.”

- OCR text exists but no gear items can be parsed:
  “Text was found, but no gear items with recognizable names and weights were detected.”

Do not hide all failures behind the same message.
