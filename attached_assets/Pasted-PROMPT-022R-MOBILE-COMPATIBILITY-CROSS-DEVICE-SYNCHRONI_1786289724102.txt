PROMPT 022R — MOBILE COMPATIBILITY & CROSS-DEVICE SYNCHRONIZATION

GOAL
Fix TrailWeigh mobile compatibility and cross-device synchronization for:
- iPhone / iPad — Safari
- Android phone / tablet — Chrome
- Desktop browsers as the comparison environment

PRIMARY USER-REPORTED FAILURE
The same signed-in TrailWeigh account shows saved Locker files on desktop, but those saved files are not appearing correctly on iPhone. Some other mobile functions are also not working correctly.

PRIORITY
Fix the saved-file synchronization problem first, then audit the mobile interface and mobile-specific browser behavior.

==================================================
Before editing:
1. Create the normal Replit checkpoint/backup.
2. Inspect the current implementation before changing it.
3. Make the smallest reasonable change.
4. Do not perform unrelated refactors.
5. Preserve user data, authentication, permissions, file IDs, saved lists, previous share fixes, background features, and prior prompt fixes.
6. Inspect the COMPLETE final diff.
7. Revert unrelated changes.
8. Run the full regression suite plus new tests.
9. Do not claim completion if an existing feature regresses.
10. Document checkpoint and final diff.

==================================================
1. DETERMINE WHERE DATA IS ACTUALLY STORED
==================================================
Inspect and document where TrailWeigh stores:
- Saved gear lists
- Locker file index/metadata
- Stable file IDs
- File names
- Gear items/categories
- Quantities and weights
- Saved checked states
- Active-file information
- Background/theme selection
- Custom themes
- Custom uploaded photos
- Shared snapshots

- Server/database/account-backed storage
- localStorage
- sessionStorage
- IndexedDB
- cookies
- memory
- other device/browser-specific storage

Do not guess.

==================================================
2. CORE ACCOUNT-SYNC REQUIREMENT
==================================================
A user signed into the SAME TrailWeigh account must be able to access the same account-owned saved gear files from supported devices.

Examples:
Desktop → iPhone
iPhone → Desktop
Desktop → Android
Android → Desktop
iPhone → Android
Android → iPhone

A saved file must retain the SAME stable file ID across devices.

Opening the file from another device must NOT silently create a duplicate.

Save must update the active saved file by its ID.
Save As must create a new file.

==================================================
3. FIND ROOT CAUSE OF MISSING IPHONE LOCKER FILES
==================================================
Investigate why files visible on desktop are missing on iPhone.

Check for:
- localStorage-only persistence
- device-local Locker index
- authentication/user-ID mismatch
- mobile Locker fetch not running
- auth initialization race
- cached empty Locker state
- Safari storage assumptions
- UI hiding data that actually exists
- responsive layout preventing rendering
- failed mobile API calls
- cookie/session/cross-origin issues
- anonymous/local saves not associated with authenticated account
- stale cache/service worker behavior

Document the ACTUAL root cause.

==================================================
4. ACCOUNT DATA VS TEMPORARY DEVICE STATE
==================================================
Account-owned data that should follow the signed-in user generally includes:
- Saved files
- Stable file IDs
- File names
- Gear items/categories
- Quantities
- Weights
- Saved checked states
- Saved background/theme references where appropriate
- Other user-created saved data intended to belong to the account

Temporary/device/session state does not necessarily need cross-device sync:
- Open/closed panels during the current session
- Temporary menus
- Temporary modals
- Hover state
- Unsaved temporary edits unless TrailWeigh intentionally restores them
- Temporary checkbox changes in shared viewer links

Do not migrate every UI preference to the server.

==================================================
5. SAFE PERSISTENCE CORRECTION
==================================================
If authenticated Locker files currently depend solely on browser/device-local storage, correct the architecture so account-owned saved files use persistent account-backed storage.

Do not create separate stores such as:
desktopLocker
iphoneLocker
androidLocker

Use one authoritative account-backed source where appropriate.

Preserve existing useful local temporary state.
