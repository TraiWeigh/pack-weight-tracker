# PART 2 — THE THEMES CONTROL IS THE DROPDOWN

## Dropdown label behavior

When the built-in default view is active, the visible dropdown label may initially read:

`Themes`

When the user selects the built-in Landscape theme, the selected state may display:

`Landscapes`

When the user selects a custom theme named `Test`, the visible dropdown label must display:

`Theme Test`

General format for a selected custom theme:

`Theme [Collection Name]`

Examples:

- Collection name: `Sierra`
- Visible selected dropdown label: `Theme Sierra`

- Collection name: `Desert`
- Visible selected dropdown label: `Theme Desert`

The user clicks the currently visible dropdown label to see all available theme options.

# PART 6 — MAXIMUM NUMBER OF THEMES

Allow a maximum of:

`10 custom themes`

The built-in Landscapes theme does not count toward this limit.

Therefore, the dropdown may contain:

- Landscapes
- Up to 10 custom themes
- Add Theme, when fewer than 10 custom themes exist

When 10 custom themes already exist:

- Disable or hide Add Theme.
- Display a clear message:
  `Maximum of 10 custom themes reached.`
- Do not create an eleventh custom theme.

When one custom theme is deleted:

- Add Theme becomes available again.

Do not count incomplete or cancelled Add Theme forms as saved themes.

# PART 7 — TEN PHOTOS PER CUSTOM THEME

Each custom theme must contain between zero and ten photos.

A newly created custom theme displays:

`10 Add Photo thumbnails`

As photos are added:

- The uploaded photo replaces one Add Photo thumbnail.
- Empty positions remain Add Photo thumbnails.
- The user can continue adding photos until all ten positions are filled.
- Display a photo count such as:
  `3/10`

At ten photos:

- No additional photo can be added.
- Display:
  `10/10`
- Disable any additional upload action.

Removing one photo makes that position available again as Add Photo.

Do not use one generic Add Photo tile followed by an empty area.

The user specifically needs ten visible thumbnail positions.

# PART 8 — FIX CLICK-TO-UPLOAD

Selecting an Add Photo thumbnail must open the operating system’s image-file picker.

After the user chooses a supported image:

- Add it to the currently selected custom theme.
- Replace that Add Photo position with the image thumbnail.
- Increase the photo count.
- Save it using the current custom-photo storage system.
- Keep the user inside the Background Edit panel.
- Do not open the image as a separate browser page.
- Do not make the image temporarily cover the whole browser.
- Do not lose the image after refresh.

Preserve the currently supported image formats.

Do not introduce unsupported image types without testing.

# PART 9 — FIX DRAG-AND-DROP PHOTO UPLOAD

The current defect is:

- The user drags an image onto Add Photo.
- Safari opens the image full-screen.
- The image is not saved to the theme.

Fix this completely.

When an image file is dragged over an Add Photo thumbnail:

- Show a visible drag-over state.
- Accept the file when dropped.
- Add it to the currently selected theme.
- Replace the Add Photo thumbnail with the new image.
- Increase the photo count.
- Persist the image after refresh.
- Keep the application on the TrailWeigh page.

The drop handler must prevent Safari’s normal file-navigation behavior.

Use the appropriate event handling, including:

- `preventDefault()`
- `stopPropagation()`

for file drag-over and drop events.

Add a safe browser-level file-drop guard when needed so dropping an image over the intended upload region cannot navigate away from TrailWeigh.

Do not block normal clicking, scrolling, or non-file interactions.

If more than one file is dropped onto one Add Photo position:

- Add only as many as there are remaining empty positions.
- Never exceed ten photos.
- Clearly ignore or report excess files.

# PART 11 — REMOVE PHOTOS

Each uploaded custom photo must have a remove control.

Requirements:

- Mouse users can access it.
- Keyboard users can access it.
- Touch users can access it without hover.
- Built-in Landscape images do not have remove controls.

Require confirmation before removal.

Cancel:

- Keeps the photo.
- Keeps the active background unchanged.

Confirm:

- Removes only that photo from the custom theme.
- Replaces the empty position with an Add Photo thumbnail.
- Decreases the count.
- Preserves all other photos.
- Preserves the custom theme.

If the removed photo is the current active background:

- Switch safely to a documented fallback.
- Prefer another photo in the same theme when available.
- Otherwise switch to Landscapes or the default background.
- Do not leave a broken image.

- The custom theme will be removed.
- Its saved photo references will be removed from the custom theme library.
- This action does not delete built-in Landscapes.

Cancel:

- Leaves the theme unchanged.
- Leaves all photos unchanged.
- Leaves the selected background unchanged.

Confirm:

- Deletes only the selected custom theme.
- Removes it from the dropdown.
- Removes its photos from the custom theme library.
- Does not delete another custom theme.
- Does not affect Landscapes.
- Reduces the custom-theme count by one.
- Makes Add Theme available again if the user was previously at the 10-theme limit.

If the deleted theme is currently selected:

- Switch immediately and safely to Landscapes.
- Change the dropdown label to `Landscapes` or the documented default `Themes` state.
- Display the Landscape thumbnails.
- Do not leave a broken theme selection.
