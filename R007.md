## Part 2 — Bottom Box Groups (§3–6)

`BottomNavBar` (single 5-box row) replaced by `BoxGroupBar` component.

### Architecture

- **4 groups** rendered as a 4× wide CSS flexbox track; `translateX` slides between them.
- All groups are in the DOM simultaneously; off-screen groups receive `aria-hidden="true"`, `visibility: hidden`, and `pointer-events: none` at rest (settled, not animating).
- During a live drag (`dragX !== 0`) or post-settle animation (`isAnimating=true` for 400 ms), all groups are briefly visible so the CSS slide feels natural.
- **No pointer capture** — window-level `pointermove`/`pointerup` listeners handle drag tracking. This is required: `setPointerCapture()` would redirect the synthesized `click` event to the nav container, preventing ChevronBox/NavBox `onClick` handlers from firing.

### Group contents

| Group | Boxes |
|---|---|
| G1 (default) | Locker \| Summary \| Add \| Search \| [→ Next] |
| G2 | [← Prev] \| Undo \| Redo \| Reset \| [→ Next] |
| G3 | [← Prev] \| Camera \| Photos \| Preview \| [→ Next] |
| G4 | [← Prev] \| Share \| More |

### Swipe gesture

- Horizontal threshold: **44 px**
- Vertical disambiguation: if `|dy| > |dx| + 6`, tracking abandoned
- Horizontal jitter guard: ignored until `|dx| > 6 px`
- No wrap-around at either end
- Short/cancelled swipe reverts to current group without haptic

### Chevrons

- Each chevron calls `goLeft()` / `goRight()` directly; no pointer capture interference
- Group 1 has no Back chevron; Group 4 has no Next chevron
- Clicking a chevron from the accessible (visible) group navigates one step

## Part 3 — Haptics (§8–9)

### Group-settle haptic (§8)

`hapticDock()` is called **once** inside `settle()` when `newIdx !== groupIdxRef.current`. It fires after state update, not during drag, not on revert (same index), not on cancellation. Tests mock `navigator.vibrate` and verify at-most-1 call per settle.

### Category reorder haptic (§9)

`gripFinish` (the drag-release handler for category reorder) calls `hapticDock()` **once** when `dstIdx !== catIdx` — i.e., only when the category landed in a new position. During drag and for same-position drops, no haptic fires. The existing R006 long-press mechanics are otherwise untouched.

## Part 5 — Weight Distribution fix (§11)

The active card content wrapper previously had `maxHeight: 300; overflowY: auto` as a hardcoded inline style. This clipped the legend and required an inner scrollbar separate from the parent `deck-scroll`.

**Fix:** The inline `maxHeight: 300` style is removed from the active card content `div`. The parent `deck-scroll` element (which already has `overflowY: auto`) now owns all vertical overflow. The legend renders without clipping regardless of how many categories exist.

---

## Part 6 — Pack Summary fix (§12)

Same root cause as Weight Distribution. The `maxHeight: 300` constraint was removed from the Pack Summary active card content wrapper. Grand Total row is now visible in a continuous scrollable panel without inner clipping.

## Remaining Defects / Known Limitations

1. **Camera / Photos — no workflow.** Stub handlers only. A future revision must design the native device integration (file picker, camera API, image-to-item pipeline).
2. **Undo / Redo disabled on fresh page load.** No history exists until the user makes a change. Buttons are present and accessible; they become enabled after the first user action. Tests verify presence only.
3. **Haptic tests are advisory.** `navigator.vibrate` is undefined in many test browsers; tests assert `count ≤ 1` (not `=== 1`) to be resilient to environments where vibrate is not exposed.
