## Spec Requirements vs. Implementation

### 1. Contextual Add Item Bar
**Spec:** Restore an `+ Add Item` bar at the bottom of every expanded category.

**Implementation:**
- A `<div>` with `data-testid="cat-add-item-btn"` button is rendered inside `{isOpen && items.length > 0 && ...}` for every open category.
- The bar carries `aria-label="Add item to <catName>"` for accessibility.
- The bar is absent (not rendered) when the category is collapsed — F01/F02 confirm this.

### 2. Long-Category Auto-Position
**Spec:** On manual open, scroll so the category header lands just below the sticky List Summary; hard upper stop = List Summary bottom edge.

**Implementation:**
- `summaryRef` callback ref attaches a `ResizeObserver` to the sticky List Summary block and keeps `summaryH` state in sync.
- `mainScrollRef` targets the main scrollable div.
- A `useEffect` on `openCatName` fires a `scrollTo()` call when a category opens manually (not during expand-all), targeting `catEl.offsetTop - summaryH`.

### 3. Add Item Bar Overflow Chevron
**Spec:** DOWN = more below, UP = at bottom; tap scrolls one page; hidden when no overflow.

**Implementation:**
- `openCatItemsRef` tracks the open category's item container via a callback ref.
- `catOverflow` state `{ above: boolean, below: boolean }` is computed by `recalcCatOverflow()` (guards stale refs with `.isConnected`).
- `recalcCatOverflow` is called on scroll (`onScroll` handler) and after any category open/close transition.
- The chevron renders only when `openCatName === catName && !allExpanded && (catOverflow.above || catOverflow.below)`.
- `data-testid="cat-overflow-chevron"` with `aria-label` matching `/scroll (down|up) to see more items/i`.
- G01/G02 confirm presence/absence and correct aria-label.

### 4. List Summary Global Expand/Collapse Chevron
**Spec:** Between item-count and Selected blocks; driven from `allExpanded || openCatName !== null`.

**Implementation:**
- Button with `data-testid="summary-expand-collapse"` in the sticky List Summary bar.
- `aria-label` toggles between `"Expand all categories"` (collapsed state) and `"Collapse all categories"` (expanded state).
- Chevron icon: `ChevronDown` when collapsed, `ChevronUp` when expanded.
- Minimum touch target: `minWidth: 44, minHeight: 44`.
- Clicking calls `handleExpandAll()` or `handleCollapseAll()` depending on state.
- `handleCollapseAll` sets `allExpanded=false` and `openCatName=null` in a single update.

## Diagnostic Findings (Test Infrastructure)

During the diagnostic pass, three issues were discovered and corrected in the test suite before the final run:

| Finding | Root Cause | Fix Applied |
|---|---|---|
| All 15 R0075 tests timed out on first run | Test URL was `http://localhost:20351/mobile-functional-v3` (wrong port) | Changed to `page.goto('/mobile-functional-v3')` (same absolute-path pattern as phase1b) |
| Readiness signal failed at mobile viewport | `getByText('LIST SUMMARY')` — that label was removed in a prior revision; only visible at desktop width | Changed to `getByTestId('active-list-name')` which is always visible after sandbox init |
| E01 item-count assertion wrong | `aria-label*="${catName}"` doesn't match new blank items (name = "Unnamed item") | Changed to count `[role="button"][aria-label*="expand details"]` rows instead |
