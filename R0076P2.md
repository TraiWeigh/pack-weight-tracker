## 2. Root Causes

### J — Scroll clamping on first open

`openCatName` useEffect fired **once** when the category was first tapped (with only 5 default items). At that point, `main-scroll.scrollHeight` was barely larger than its `clientHeight`, so `ms.scrollTop = target` was silently **clamped** to the available maximum (≈ 32–40 px) instead of the needed 69 px.

`isCatLong` was absent from the effect's dependency array, so the effect never re-fired when `isCatLong` became `true` (after items were added, making the content tall enough for the full scroll).

Additionally, `behavior: 'instant'` in `scrollTo()` is **not synchronous** in Chrome — it queues an animation task. A second RAF fired mid-animation, reading a partial position.

### K — `item-delete-row` testid absent; `expandedItem` effect already correct

The auto-reveal `useEffect` was implemented correctly (fires on `[expandedItem, isCatLong]`, waits 200 ms, measures Delete row vs. viewport bottom, scrolls only if needed). The missing piece was the `data-testid="item-delete-row"` attribute on the Delete Item row `<div>` — set only when `isExpanded && isCatLong && openCatName === catName`.

### L — `onSave` prop not wired to BoxGroupBar

`BoxGroupBarProps` was missing `onSave: () => void`, and the Group 4 JSX had `Back | Share | More`. `onSave={handleSave}` was not passed at the usage site.

6. **`openCatName` useEffect — RAF1** — `ms.style.overflowY = 'auto'` before measuring/scrolling so the bounded state does not suppress the scroll.  
   RAF2 calls `remeasureLongMode()` after the corrective offset is applied — `isCatLong` state re-set (no change) and `maxItemH` re-measured from the now-correct DOM positions.

8. **`data-testid="item-delete-row"`** — set on the Delete Item row `<div>` conditionally:  
   `data-testid={isExpanded && isCatLong && openCatName === catName ? 'item-delete-row' : undefined}`

9. **`onSave={handleSave}`** — added at the `<BoxGroupBar>` usage site.

10. **Group 4 comment** — corrected to `Back | Save | Share | More`.

## 6. Diagnostic Notes

### `ms.scrollTop = N` vs. `scrollTo({ behavior: 'instant' })`

Chrome does **not** treat `behavior: 'instant'` as synchronous at the property-assignment level — it queues a microtask similar to smooth scroll. Setting `.scrollTop` directly is the only guaranteed-synchronous approach.

### Why `isCatLong` must be in the effect deps

The scroll fires in a double-RAF inside the `openCatName` useEffect. On first open the category is short; content height may not accommodate the full delta scroll. Only after `isCatLong=true` (items added → content tall enough) can the correct `ms.scrollTop = 69` land without clamping. Adding `isCatLong` ensures the corrective re-fire happens automatically.

### Playwright `[aria-hidden!="true"]` selector

Invalid CSS — the `!=` attribute selector is not part of CSS Level 3/4. Use `.filter({ visible: true })` instead.

### `el.click()` via `evaluate()` for off-screen BoxGroupBar buttons

Playwright's `.click()` — even with `{ force: true }` — rejects elements positioned outside the viewport box. Dispatching via `el => el.click()` inside `evaluate()` fires the handler without pointer-position constraints.
