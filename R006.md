# R006 — Long-Press Reorder, Handle Removal, Shell Pinning, Dropdown Fix, List Actions

Route: `/mobile-functional-v3` · File: `artifacts/pack-checklist/src/pages/MobileFunctionalV3.tsx`

## Summary

R006 removes the six-dot reorder handles entirely and replaces them with a
long-press-to-reorder gesture on the category bar itself, smooths the reorder
motion (displaced bars glide instead of jumping), locks the app shell to the
viewport (no page rubber-band), fixes the Trail palette dropdown clipping,
and trims More → List Actions (Expand All / Collapse All / Summary removed,
View / Print added).

## Part 1 — Six-dot handles removed

- The grip button (`Drag to reorder … category`) and its two reserved grid
  columns (36px handle + 10px gap) are deleted.
- Category content grid is now `minmax(0,1fr) minmax(44px,auto)` — the name
  and subtitle reclaim the full width; nothing else moved.
- `GripVertical` import removed; no `aria-grabbed` remnants.

## Part 2 — Long-press reorder (documented values)

- **Threshold: 400 ms** stationary hold (`LONG_PRESS_MS = 400`).
- **Jitter slop: 10 px** (`HOLD_SLOP_PX = 10`) — movement within the slop
  never cancels the hold; movement beyond it *before* the threshold hands the
  gesture to scroll (vertical) or slide-to-delete (horizontal).
- Quick tap keeps all existing behavior: wedge toggles the accordion, name
  opens Category Options.
- On activation: the card floats (same elevation/scale as before), one subtle
  `navigator.vibrate(10)` haptic fires **only** where genuinely supported (no
  visual fake), and the trailing click is swallowed so the accordion never
  toggles from a reorder.
- After activation the drag owns the gesture: a non-passive window `touchmove`
  preventDefault blocks browser scroll takeover; slide-to-delete rows are
  inert (`reorderActive` prop); all R005 cancel paths are preserved
  (pointercancel by id/list-target, window blur, visibilitychange, unmount).
- A hold cannot arm while another drag is active (no mid-drag hijack).
- Long press produces no text selection (R005 user-select rules retained).

## Part 3 — Smoother reorder motion

- During a drag the DOM order stays **fixed** (original order) — the list is
  no longer live re-spliced, which was the source of the jumping.
- Displaced bars glide into their temporary positions via
  `translateY(±draggedHeight)` with a `motionDuration()` ease-out transition;
  the dragged card follows the finger 1:1 exactly as in R005.
- Dim/undim uses the same quick transition; release settles flush (no
  transforms, no dim, no floating remnants — asserted in tests).
- Reduced motion: transitions on category cards are disabled under
  `prefers-reduced-motion: reduce`; state changes remain instant and clear.
- Slot detection subtracts each card's rendered transform, so untransformed
  midpoints drive the target index (no feedback loops).

## Part 4 — Gesture arbitration (explicit)

| Gesture | Winner |
| --- | --- |
| Tap ≤ slop, release < 400 ms | Accordion / Category Options (unchanged) |
| Stationary hold ≥ 400 ms | Reorder mode |
| Vertical move > 10 px before 400 ms | List scroll |
| Right-edge horizontal move > 10 px before 400 ms | Slide-to-delete |
| Any movement after activation | Reorder owns the gesture |

## Part 5 — App shell pinned to the viewport

- `html:has(.tw-v3-root), body:has(.tw-v3-root)` get
  `overscroll-behavior:none; height:100%; overflow:hidden` — no page
  rubber-band, no blank band above/below the app.
- Header and bottom nav stay anchored; only the internal list region scrolls
  (`overscroll-behavior:contain` on the main scroller). No trapped scrolling.

## Part 6 — Trail palette dropdown

- Root cause: the shared Weight Distribution card ships `overflow-hidden`,
  which clipped the absolutely-positioned palette menu inside the flattened
  V3 deck panel.
- V3-scoped CSS fix (no shared-component edits): `.tw-flat-wd > div` gets
  `overflow:visible`, and the menu is pinned to the panel's right edge with
  `max-width:calc(100vw - 32px)` — it favors the right side and stays fully
  inside the viewport at 320 / 375 / 390 / 430 (test-verified at all four).

## Part 7 — List Actions cleanup

- Removed rows: **Expand All**, **Collapse All**, **Summary** (and their
  now-unused handlers); remaining rows unchanged in order and styling:
  Save, Undo, Redo, Reset, Checklist.
- Card subtitle updated ("Save, undo, reset, views").

## Part 8 — View / Print

- New row **View / Print** directly after Checklist, same flat row pattern.
- Routes to the existing print flow (`handlePrint`): generates/downloads the
  PDF view and opens the browser print dialog — no new print implementation.
- The Share & Print card is untouched (no duplicated Share controls).

## Scope

- App source changes are confined to `MobileFunctionalV3.tsx` only. No
  Checklist.tsx / desktop / database / auth / deployment changes.
